# FlyArchive

English: [README.md](README.md)

Свой архив документов с поиском — на своей машине. Кладёшь файлы во входящую папку, архив проверяет их, принимает и
индексирует; искать можно самому или дать архив языковой модели — локальной или внешней — по протоколу MCP (Model Context
Protocol: так модель получает инструменты архива) и по токену, который ты выдал.

- **Поиск по смыслу и по словам.** Векторы и полнотекстовый индекс в одной таблице, всё считается локально.
- **Пополнение со строгой приёмкой.** Тип файла определяется по содержимому, а не по расширению; программы и подозрительное
  уходят в карантин, спорное ждёт твоего решения, повторы не принимаются. Ничего не теряется: у каждого файла есть квитанция, а то, что архив не взял, возвращается в папку возврата (убираются только
  сохранённые точные копии и то, что не содержимое: пустые файлы и следы систем вроде `__MACOSX` и `.DS_Store`; а при судьбе «стирать» для служебных файлов убираются и файлы по служебным
  шаблонам имён, по умолчанию они возвращаются).
- **Модели работают с архивом через инструменты.** Поиск, чтение документов целиком, схемы, графики, сборка файлов Word,
  Excel, PowerPoint и PDF. Доступ — по токену с уровнем «чтение» или «полный», каждое обращение пишется в журнал.
- **Наружу — одна дверь.** С других машин архив виден только через шлюз в частной сети: MCP по токену и подписанные ссылки
  на документы. Удаление, решения по очереди и выпуск токенов — только на машине архива.

Версия 0.1. Интерфейс команды и сообщения — на русском; экран плагина для веб-оболочки — на английском.

## Что нужно

| Что | Зачем | Обязательно |
|---|---|---|
| Linux (под Windows — WSL2) | замки файлов, песочница, службы пользователя | да |
| Python 3.10 или новее и библиотеки из `requirements.txt` | архив, приёмка, поиск | да |
| Служба векторов с интерфейсом Ollama (проще всего — сама Ollama) и моделью `bge-m3`, около гигабайта на диске | векторы для индекса и запросов | да |
| Библиотеки из `requirements-optional.txt` | форматы Office и писем, графики, сборка PDF, разбор с таблицами | по форматам |
| systemd (службы пользователя) | постоянная работа: поиск, документы, MCP, разбор по расписанию | нет: всё запускается и руками |
| bubblewrap (`bwrap`) | просмотр непроверенных файлов, оболочки внешних моделей в песочнице; на обычной Ubuntu 24.04 вне WSL2 песочницу может запретить настройка системы, и `flyarchive doctor` это покажет | нет |
| docker | просмотр файлов Office и HTML | нет |
| 7z, graphviz | архивы 7z и rar во входящих; схемы | нет |
| Локальная модель на сервере с интерфейсом OpenAI | проверка документов моделью, описание картинок и сканов | нет |
| Оболочка DeepSeek Harness (`dsh`) | разговор с моделью в браузере и раздел «Archive» | нет |
| Tailscale | доступ к архиву с других своих машин | нет |

Чего не хватает на твоей машине и что без этого не будет работать, скажет `flyarchive doctor`.

## Первые пять минут

Нужны: Linux (под Windows — WSL2), Python 3.10 или новее (на Debian и Ubuntu — вместе с пакетом `python3-venv`), git и служба векторов ollama
с моделью bge-m3. Программы вроде bwrap, 7z, docker, systemd и оболочка DSH не обязательны: поиск работает и без них.

Службу векторов ставят отдельно, до блока ниже: блок её не ставит, а только скачивает для неё модель. Служба — программа Ollama. Скачай её на странице загрузки
на сайте проекта Ollama: [ollama.com/download](https://ollama.com/download). Команду установки бери оттуда и прочитай её до запуска: здесь её нет.
Ollama должна работать, пока работает архив. Там, где её запускает система, она уже запущена; под WSL2 без systemd запусти в соседнем терминале
`ollama serve` и не закрывай его. Модель скачивает строка `ollama pull bge-m3` из блока: около гигабайта на диске. Что служба отвечает, покажет
`flyarchive doctor` (строка «служба векторов отвечает»); если нет, смотри разбор сбоев в [docs/operations.md](docs/operations.md), случай «Служба
векторов не установлена или не запущена».

Блок ниже ведёт от клонирования до найденного документа: виртуальное окружение, проверка окружения, заведение архива, три выдуманных документа
из `examples/`, разбор, поиск. Без служб и без оболочки: всё делает команда. Виртуальное окружение создаётся первым: на Ubuntu 24.04 и Debian 12
системный `pip` отказывает (`externally-managed-environment`), если ставить библиотеки вне окружения, а в окружении (папка `.venv` рядом с кодом)
системный Python остаётся нетронутым. Окружение нужно включать в каждой новой оболочке: `. .venv/bin/activate` из каталога клона.

Таймер разбора не ставится (`--no-timer`): после блока в системе нет ни файлов служб, ни включённого таймера, а разбор запускается вручную,
`inbox run`. Постоянный разбор по расписанию ставит `flyarchive install` или `flyarchive inbox set` без `--no-timer`. Разбор берёт файл, только когда
тот перестал меняться (по умолчанию 30 секунд), поэтому `inbox run --wait` ждёт около полуминуты, прежде чем ответить. Проверка моделью выключена
(`--llm off`): без локальной модели всё непроверенное ждало бы твоего решения в очереди; задать модель можно позже, настройка `llm_local_model`.
В конце `init` и `doctor` спрашивают службу векторов, а первый запрос может поднимать модель с диска: `init` иногда ждёт до минуты, команда не зависла.

<!-- first-five-minutes -->
```bash
git clone https://github.com/andrewsabn/flyarchive.git flyarchive && cd flyarchive
python3 -m venv .venv && . .venv/bin/activate
python3 -m pip install -r requirements.txt
ollama pull bge-m3                                # служба ollama уже должна работать; модель — около гигабайта
python3 tools/flyarchive doctor                   # что не хватает; «служба векторов» обязательна, остальное по желанию
python3 tools/flyarchive init
python3 tools/flyarchive inbox set --path ~/flyarchive-inbox --llm off --cloud off --no-timer
cp examples/* ~/flyarchive-inbox/
python3 tools/flyarchive inbox run --wait
python3 tools/flyarchive search "перенос релиза"
python3 tools/flyarchive search "tally file format"   # то же на английском: образцы есть на обоих языках
```

`doctor` называет, чего не хватает (библиотеки по форматам: `python3 -m pip install -r requirements-optional.txt`). Команда `flyarchive`
без `python3 tools/` появляется после постоянной установки (раздел ниже): `flyarchive install` кладёт ссылку на неё в `~/.local/bin`
и ставит службы.

## Что должно получиться

В конце `inbox run` — номер пачки (`ГГГГММДД-ЧЧММСС`, время запуска) и счёт по решениям; три образца принимаются, и их квитанции лежат в каталоге архива:

```
Пачка ГГГГММДД-ЧЧММСС:
  Принято: 3
Квитанции: <каталог архива>/квитанции/ГГГГММДД-ЧЧММСС.jsonl
```

В образце вместо даты и времени стоят обозначения. Поиск печатает находки по порядку; начало вывода `search "перенос релиза"`:

```
 1. [0.0297] ГГГГ-ММ-ДД  ГГГГММДД-ЧЧММСС  protokol-vstrechi.md
    входящие/ГГГГММДД-ЧЧММСС/protokol-vstrechi.md
    # Протокол встречи команды «Лодочный журнал» Встреча выдуманной команды, которая делает приложение для записи лодочных прогулок. Любое сходство с …
```

Первая строка находки: номер, оценка в квадратных скобках, дата документа, раздел, название. У принятого через входящую папку раздел — номер пачки,
а дата — время изменения файла: у образцов своей даты нет. Вторая строка — путь в архиве (`входящие` — база принятого через входящую папку), третья —
начало текста (до 220 знаков; здесь оно обрезано). Оценка нужна, чтобы сравнивать находки между собой: у тебя числа будут другие, главное — какой
документ первый. Запрос `search "tally file format"` первым ставит `file-format.txt`. Если находок нет, команда пишет «ничего не найдено».

Если в выводе `inbox run` есть строки `замечание:` о службе векторов, документы приняты, но ещё не проиндексированы, и поиск пока их не найдёт: разбор —
в [docs/operations.md](docs/operations.md), случай «Служба векторов не установлена или не запущена».

## Постоянная установка

```bash
. .venv/bin/activate                           # окружение из каталога клона: службы и запускалка запомнят этот Python, а не системный без библиотек
python3 tools/flyarchive install --dry-run     # что будет записано и запущено; ничего не трогает
python3 tools/flyarchive install               # архив, службы и таймер разбора, команда в ~/.local/bin, запуск
```

Службы слушают только петлю: поиск, сервер документов и переходник MCP. Данные, журналы и секреты лежат в каталоге архива
(`~/flyarchive` или переменная `FLYARCHIVE_HOME`), код — там, откуда шла установка. Команда `flyarchive` ставится запускалкой `bin/flyarchive` в каталоге архива и ссылкой на неё в `~/.local/bin`: она идёт тем Python,
которым шла установка, и окружение в новой оболочке включать для неё не нужно. Оболочка `dsh` и её плагин ставятся,
если `dsh` есть на машине; шлюз в частную сеть — если заданы его адреса или по ключу `--gateway auto`.
Под WSL2 службам пользователя нужен включённый systemd: строка `systemd=true` в разделе `[boot]` файла `/etc/wsl.conf`, затем перезапуск WSL
(`wsl --shutdown` в Windows). Проверка моделью включена по умолчанию: пока локальная модель не задана, каждый документ ждёт твоего решения в очереди;
задай модель (настройка `llm_local_model`) или выключи проверку: `flyarchive inbox set --llm off`.
Подробности, настройки и обновление — в [docs/operations.md](docs/operations.md).

## Подключить модель

```bash
flyarchive token add ассистент --level read    # токен показывается один раз
flyarchive connect claude                      # готовая настройка MCP для оболочки; есть codex, opencode, dsh, generic
flyarchive journal -n 20                       # кто и что спрашивал
```

Модель работает с архивом через переходник MCP, и он должен работать. После «первых пяти минут» служб нет: поставь их постоянной установкой (раздел выше) или
запусти три службы руками, `tools/webui.py`, `tools/office_server.py` и `tools/mcp_server.py` (раздел «Без служб и без оболочки» в
[docs/operations.md](docs/operations.md)).

Модель получает инструменты архива и работает только через них. Как ей ими пользоваться — в
[docs/for-llm.md](docs/for-llm.md): этот документ можно отдать модели целиком как указание.

## Пополнять архив

```bash
flyarchive inbox status          # что настроено и что ждёт
flyarchive inbox run --wait      # разобрать входящую папку сейчас
flyarchive queue list            # что ждёт твоего решения
```

Положи файл, папку или архив во входящую папку. Проход приёмки берёт файлы, которые перестали меняться, проверяет и
раскладывает: принятое — в корпус и индекс, спорное — в очередь, опасное — в карантин, остальное — в папку возврата; пустые файлы и следы систем (`.DS_Store`, `__MACOSX`) убираются.
Пока локальная модель не задана, а проверка моделью включена, спорным считается всё: документы ждут в очереди (`flyarchive queue list`), пока ты не
зададишь модель или не выключишь проверку (раздел «Постоянная установка»).

## Тесты

```bash
. .venv/bin/activate                                 # то же окружение, что при установке; в новой оболочке его надо включить снова
python3 -m pip install -r requirements.txt -r requirements-optional.txt -r requirements-dev.txt
python3 -m pytest
```

Тесты идут в том же виртуальном окружении, где стоят библиотеки: вне него система не даст их поставить. Полный прогон идёт около получаса: тестов несколько тысяч. Тесты не трогают
ни твой архив, ни твои службы: у каждого свой временный каталог и подставные программы. На свежем клоне набор не показывает красного и на одних
обязательных библиотеках (`requirements.txt` и `requirements-dev.txt`): тест, которому нужна библиотека по формату или программа вроде node, bwrap,
docker, 7z или graphviz, пропускается с причиной, которая её называет (тест с настоящей песочницей — и там, где `bwrap` стоит, а система не даёт её создать). Пропуск — не зелёный: прочитай итоговые строки (`-rs`).

## Ограничения

- Работает на Linux; под Windows — в WSL2. На macOS не проверялось и не запустится: нужны замки и песочница Linux.
- Команда, её сообщения и имена каталогов в архиве (`входящие`, `очередь`, `карантин`, `квитанции`) — на русском.
  Описания картинок и указания модели при проверке тоже русские.
- Архив рассчитан на одного владельца на одной машине. Разделения прав между пользователями нет.
- Служба векторов должна понимать запрос Ollama (`/api/embed`); размерность векторов задаётся при заведении архива.
- Проверено на Ubuntu 24.04 (WSL2), Python 3.12, версиях библиотек из файлов зависимостей.
