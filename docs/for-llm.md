# Как языковой модели работать с этим архивом

English: [docs/en/for-llm.md](en/for-llm.md)

Этот файл можно отдать модели целиком как системное указание. Он описывает
инструменты, порядок работы и особенности данных, о которых иначе не
догадаться.

## Что за архив

Личный архив документов владельца: файлы, письма и другие материалы, которые он положил в архив сам или загрузил выгрузкой. Что именно в нём лежит,
зависит от владельца: у каждого архива свой состав.

Архив разложен по базам. Какие базы есть в этом архиве и что лежит в каждой, сказано в описании
инструмента `search_archive`: оно собирается из таблицы источников владельца. На свежем архиве база одна, `входящие`: в неё попадает всё, что принято
через входящую папку и передано по MCP. Другие базы заводит владелец, когда загружает свои выгрузки. Базы разделены намеренно: когда вопрос про одну из них,
ограничь поиск параметром `source`.

Так могут выглядеть имена баз (образец; в каждом архиве свои, а настоящие — в описании инструмента):

| База | Что это |
|---|---|
| `входящие` | принятое через входящую папку и переданное по MCP; есть в каждом архиве |
| `wiki` | страницы вики команды |
| `wiki-att` | вложения этих страниц |
| `tracker` | задачи из системы учёта задач |
| `mail-alpha` | почта одного ящика |

## Вход

Каждый запрос несёт токен: заголовок `Authorization: Bearer <токен>`. Токен
выдаёт владелец архива командой `flyarchive token add`. Без токена — ответ 401.

Готовую настройку для оболочки печатает владелец: `flyarchive connect <оболочка>`.

Адрес MCP на машине архива — `http://127.0.0.1:8767/mcp` (порт по умолчанию). С другой машины частной сети — `http://<имя узла архива в tailnet>:8780/mcp`
(tailnet — частная сеть, которую владелец собрал программой Tailscale; имя узла — имя машины архива в ней); там работает только MCP, прямых
адресов поиска и чтения нет. Документ открывается по ссылке `url` из ответа.

| Уровень токена | Что можно |
|---|---|
| `read` | поиск и чтение документов |
| `full` | ещё создание файлов: схемы, графики, документы |

Инструменты не своего уровня по MCP не показываются; вызов по имени получает
отказ. Удалять документы и выпускать токены по сети нельзя вовсе.

Ссылки `url` в ответах подписаны и живут сутки — их можно отдавать человеку,
они открываются в браузере без токена. Через сутки запроси документ заново.

Каждое обращение пишется в журнал под именем клиента.

## Инструменты

Через MCP они приходят под именами `mcp__flyarchive__*` (оболочка добавляет к имени инструмента имя сервера). Те же инструменты описаны в OpenAPI: описание отдают
службы поиска и документов по адресу `/openapi.json`, и там они названы по-своему. Ниже — своё имя, адрес и договор.

### search_archive — найти документы

`GET http://127.0.0.1:8765/api/search`

| Параметр | Что значит |
|---|---|
| `q` | запрос обычными словами, обязателен |
| `k` | сколько вернуть, 1–20, по умолчанию 10 |
| `source` | ограничить базой (имена баз — в описании инструмента); несколько через запятую |
| `space` | раздел внутри базы: проект, пространство вики, почтовый ящик или номер пачки |
| `since` | не старее даты: `ГГГГ`, `ГГГГ-ММ` или `ГГГГ-ММ-ДД` |

Ответ:

```json
{"query": "формат файла счётчиков", "count": 3,
 "results": [{"score": 0.0166, "title": "…", "date": "2024-06-11",
              "base": "wiki", "space": "boats",
              "path": "wiki/boats/…/tally-format.html",
              "url": "http://127.0.0.1:8765/doc?p=…",
              "text": "фрагмент до 420 символов"}]}
```

`path` — ключ для чтения документа целиком. `url` — готовая ссылка для
человека, приводи её в ответе.

Ограничения намеренные: фрагмент обрезан до 420 символов, весь ответ — до
6000 символов текста. Сверх бюджета находки перечисляются без текста: значит
нашлось больше, уточни запрос.

### read_document — прочитать документ целиком

`GET http://127.0.0.1:8766/read` — параметры `path` (из выдачи поиска) и
`pages`.

Читает `pdf`, `docx`, `xlsx`, `pptx`, `msg`, `eml`, `vsdx`, а также `txt`, `md`,
`csv`, `json`, `xml`. Старый двоичный `vsd` не читается: читается `vsdx`. Для pdf `pages` задаётся как `1-5` или `3,7`, для xlsx —
именами листов через запятую. Без `pages` берутся первые 40 страниц. Ответ
обрезается на 60 000 символах.

Не читает `html`, `sql`, `log`, `svg`, `bpmn`, `yaml`, `drawio`, `ini`, `tsv`,
хотя в поиске они есть: для `html` бери `read_document_rich`, для остальных
довольствуйся фрагментом из выдачи.

Быстро, доли секунды. Таблицы при этом разваливаются в поток слов.

### read_document_rich — прочитать с таблицами

`GET http://127.0.0.1:8766/rich` — те же параметры.

Разбирает вёрстку через Docling: таблицы остаются таблицами в разметке
markdown. Дополнительно читает старые форматы: `doc`, `xls`, `ppt`, `odt`,
`ods`, `odp`, `epub`.

Медленнее обычного чтения в десятки раз. Бери, когда в документе важна
таблица: расписание, смета, список задач, бюджет. Для вопроса «о чём документ»
хватает `read_document`.

### make_landscape — схема по краткому описанию

`POST http://127.0.0.1:8766/landscape`

```json
{"title": "Схема приложения", "direction": "TB",
 "groups": [{"name": "Клиенты", "nodes": ["Телефон", "Сайт"]},
            {"name": "Сервер", "nodes": ["Журнал прогулок", "Карты маршрутов"]}],
 "edges": [["Телефон", "Журнал прогулок"], ["Сайт", "Журнал прогулок", "через интернет"]]}
```

Оформление — рамки групп, цвета, направление — делает сервер. Это основной
инструмент для карт систем, архитектур и схем интеграций. Возвращает ссылку на
картинку; вставляй её в ответ как `![подпись](url)`.

### make_diagram — схема исходником graphviz

`POST http://127.0.0.1:8766/diagram` — поля `dot` и `fmt` (`png` или `svg`).

Бери только для того, чего не выразить группами и связями. **Держи исходник
короче трёх тысяч символов.** Длинный вызов может оборваться при передаче, не
дойти до сервера, и попытка выглядит как молчание — легко уйти в
бесконечный круг повторов.

### make_chart — график

`POST http://127.0.0.1:8766/chart`

```json
{"kind": "bar", "title": "Прогулки по месяцам", "ylabel": "штук",
 "labels": ["янв", "фев", "мар"], "series": {"завершено": [10, 14, 9]}}
```

`kind`: `bar`, `barh`, `line`, `pie`.

### make_document — собрать файл

`POST http://127.0.0.1:8766/document` — поля `kind` (`docx`, `xlsx`, `pptx`,
`pdf`), `title`, `blocks`.

- для `docx` и `pdf`: `[{"type": "heading|text|bullets|table", "value": …}]`
- для `xlsx`: `[{"name": "Лист", "value": [["строка"], ["строка"]]}]`
- для `pptx`: `[{"name": "Заголовок слайда", "bullets": ["пункт"]}]`

Для `pdf` с русским текстом на машине архива нужен шрифт с кириллицей; если сервер отказал (503, «нет шрифта с кириллицей для pdf»), скажи об этом владельцу, а не повторяй вызов.

### submit_document — передать документ в архив

Нужен токен уровня `full`. Документ не попадает в архив сразу: он ложится во входящую папку и проходит приёмку —
тип по содержимому, правила безопасности, сверку с тем, что уже есть, проверку моделью. В поиске он появится после
ближайшего разбора, обычно в пределах получаса, в базе `входящие`.

```json
{"name": "submit_document", "arguments": {"name": "отчёт-за-сентябрь.pdf", "content_base64": "JVBERi0xLjQK…"}}
```

- `name` — имя файла с расширением, без каталогов.
- `content_base64` — содержимое в base64, до 16 МБ.

В ответе `sha256` и размер — по ним видно, что файл дошёл целым. Документ с находками попадёт на утверждение
владельцу, программа — в карантин, повтор того, что уже есть, принят не будет. Не передавай документ дважды.

## Порядок работы

**Сначала ищи, потом отвечай.** На любой вопрос о работе, проектах, системах,
документах, переписке или людях первым делом вызывай `search_archive`. Не
отвечай по памяти: в архиве конкретные факты, даты и имена файлов.

**Держи счёт вызовов.** Обычно хватает одного-двух поисков, на широкий вопрос —
не больше четырёх. Каждый ответ занимает место в контексте. Двадцать вызовов
подряд переполняют окно, и разговор обрывается.

**Не повторяй запрос, который уже делал.** Нашлось мало — переформулируй один
раз синонимами. Если и после этого пусто, так и скажи: в архиве нет.

**`k` больше 10 ставь только при явной просьбе** показать много.

**Читай документ целиком по одному и только когда нужно.** Стостраничный pdf
съедает контекст быстрее десяти поисков.

**Если инструмент не ответил — смени подход,** а не повторяй то же самое:
сократи вызов, разбей задачу, возьми `make_landscape` вместо `make_diagram`.

**Опирайся только на найденное.** По каждому источнику приводи название
документа, базу и ссылку из поля `url` — человеку нужно открыть оригинал.
Если факта в выдаче нет, скажи об этом, а не достраивай.

## Как устроен поиск, и что из этого следует

Гибрид: смысловой поиск по векторам (по умолчанию модель `bge-m3`) и точное совпадение слов (BM25).
Списки объединяются обратным рангом, результат умножается на свежесть
документа. Повторы схлопываются по тексту.

Отсюда практические следствия.

**Формулируй запрос содержательно, а не ключевыми словами.** Смысловая часть
работает лучше на живой фразе: `формат файла счётчиков` найдёт
больше, чем `счётчики`.

**Полнотекстовая часть собрана с английской морфологией.** «Прогулка» и «прогулки»
для неё разные слова. Если ищешь термин, дай пару форм или синонимов в одном
запросе.

**Даты настоящие.** У документа стоит его собственная дата, а не день копирования в архив. Берётся первая из найденных: дата из свойств файла
(у письма — из заголовка), дата в имени файла, время изменения файла, день приёмки в архив; вложению письма ставится дата письма.
`since` можно использовать для любой базы. Формат — год, год и месяц или полная дата:
`ГГГГ`, `ГГГГ-ММ`, `ГГГГ-ММ-ДД`; на другое поиск ответит отказом и скажет, как писать.

**Кавычки фразой не делают.** Поиск по словам собран без позиций слов:
`"маршрут прогулки"` ищется как два слова. Кавычки не мешают, но и не помогают.

**Свежесть влияет на порядок выдачи.** Документ без даты проигрывает
«свежему». Если ищешь заведомо старое, добавь год в запрос словами.

**Одинаковые находки схлопываются, близкие копии остаются.** Один и тот же документ может лежать в архиве в нескольких копиях,
например вложение, пришедшее с несколькими письмами. Схлопывание убирает из выдачи находки с одинаковым началом
текста (первые 400 знаков), но если видишь три близких документа с одинаковым названием — скорее
всего это один и тот же файл.

**Картинки и сканы без текстового слоя находятся по описанию.** Их описывает локальная модель со зрением, если владелец её
задал; описание попадает в индекс как текст документа. Оно сделано моделью и может ошибаться в мелочах: за точным значением
открывай оригинал по ссылке. Пока описания нет, документ по содержимому не находится: ищи письмо, к которому он был приложен, —
по дате, теме или участникам.

## Примеры

```
# поиск
search_archive q="формат файла счётчиков" k=8
search_archive q="перенос релиза" source="wiki"
search_archive q="справочник единиц измерения" source="wiki,tracker" since="2024-06"

# чтение
read_document path="<path из выдачи>" pages="1-5"
read_document_rich path="<path>"        # если нужна таблица

# схема
make_landscape title="Схема" groups=[…] edges=[…]
```
