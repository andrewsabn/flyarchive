# Установка и эксплуатация

English: [docs/en/operations.md](en/operations.md)

Руководство для владельца установки: человека с Linux, который ставит FlyArchive у себя, заводит архив и следит за ним. У тебя свой каталог, свои
модели и свой архив, поэтому ничего «как у автора» от тебя не требуется: умолчания взяты из кода (справочник печатает `python3 tools/settings.py --reference`),
а всё, что зависит от твоей машины, названо настройкой. Как устроен архив — в `docs/architecture.md`, требования по карточкам — в `docs/requirements.md`, как модели пользоваться архивом —
в `docs/for-llm.md`. Путь от клонирования до первого найденного документа за несколько минут — в начале `README.md`.

Команда архива — `flyarchive` (файл `tools/flyarchive`). Пока установка не положила её в путь поиска, зови её по пути из каталога репозитория:
`python3 tools/flyarchive doctor`. Дальше в тексте она пишется просто `flyarchive`. Справка команды и всех её частей — `--help`; она, сообщения
и названия рабочих каталогов архива (`входящие`, `очередь`, `карантин`, `квитанции`, `удалённое`) русские, экран плагина оболочки — английский.

## Что нужно и проверка окружения

### Система и Python

Только Linux: код опирается на `fcntl`, `resource`, bubblewrap и `systemctl --user`. Под Windows работай в WSL2. На любой другой системе каждая
команда, кроме справки, отвечает отказом и кодом возврата 2. Нужен Python 3.10 или новее (ниже не ставятся обязательные библиотеки); проверено
на 3.12. Серверы и команда написаны на стандартной библиотеке Python плюс библиотеки из файлов ниже.

Библиотеки ставь в виртуальное окружение: на Ubuntu 24.04 и Debian 12 системный `pip` вне окружения отказывает (`externally-managed-environment`).
На Debian и Ubuntu для него нужен пакет `python3-venv`. Окружение создают и включают из каталога клона, и в каждой новой оболочке включают снова:

```bash
python3 -m venv .venv && . .venv/bin/activate
```

### Файлы зависимостей

| Файл | Что в нём | Что будет, если не ставить |
|---|---|---|
| `requirements.txt` | обязательное: `lancedb`, `pyarrow`, `pymupdf` | нельзя завести таблицу индекса и искать; pdf не проверяются при приёмке и их текст не попадает в индекс |
| `requirements-optional.txt` | по желанию: библиотеки форматов и возможностей, по одной на строку с пояснением | не работает только то, что названо в пояснении |
| `requirements-dev.txt` | `pytest`, для тестов | нельзя запустить тесты |

```bash
. .venv/bin/activate                                       # окружение из раздела «Система и Python»
python3 -m pip install -r requirements.txt                 # обязательное
python3 -m pip install -r requirements-optional.txt        # всё по желанию сразу (или одну библиотеку: python3 -m pip install ИМЯ)
```

Что даёт каждая библиотека из `requirements-optional.txt`:

| Библиотека | Что открывает | Без неё |
|---|---|---|
| `Pillow` | просмотр png и jpeg, уменьшение страниц перед отправкой модели | картинки не показываются, страницы уходят модели как есть |
| `python-docx` | документы Word (.docx) | не попадают в индекс и не читаются сервером документов |
| `openpyxl` | таблицы Excel (.xlsx, .xlsm) | то же |
| `python-pptx` | презентации (.pptx) | то же |
| `extract-msg` | письма Outlook (.msg) | не разбираются при приёмке и не попадают в индекс; `flyarchive known build` не читает их ключи и пишет замечание; принятие письма из очереди и проход входящих тоже называют библиотеку в замечании |
| `olefile` | старые форматы Office (.doc, .xls, .ppt) и .msg | опознаются как «не документ» и не принимаются |
| `docling` | разбор документов с таблицами в сервере документов, распознавание сканов на месте; тяжёлая | этих двух чтений нет |
| `matplotlib` | графики сервера документов | инструмент графиков отвечает отказом (код 503) с названием библиотеки и подсказкой, что поставить |
| `reportlab` | создание pdf сервером документов (для русского текста нужен ещё шрифт с кириллицей, см. «Программы») | pdf не собираются |

Без этих библиотек архив продолжает работать, но не всё: документ остаётся в архиве, а его текста в индексе нет, и сам по себе приём об этом не
предупреждает. Что именно не работает без каждой библиотеки, называет `flyarchive doctor`. Сервер документов, которому нужна недостающая библиотека или
программа, отвечает на запрос отказом с её названием и подсказкой (код ответа 503), а не обрывом соединения, и остаётся жив; модель через MCP получает это
как ошибку инструмента. Visio сервер документов читает только в формате `.vsdx`: старый двоичный `.vsd` он не читает и отвечает на него ошибкой с пояснением.

### Программы

Ни одна из них не обязательна для ядра (приём файлов, индекс, поиск); каждая открывает свою возможность.

| Программа | Пакет Ubuntu и Debian | Для чего | Без неё |
|---|---|---|---|
| `bwrap` (bubblewrap) | `bubblewrap` | песочница: просмотр непроверенных файлов, запуск оболочек внешних моделей, описание изображений (картинку готовит просмотр) | просмотр, песочница и описание изображений не работают; на обычной Ubuntu 24.04 вне WSL2 песочницу может запретить настройка системы, и `flyarchive doctor` это покажет |
| `7z` (или `7za`, `7zz`) | `p7zip-full` (даёт `7z` и `7za`); в новых выпусках есть и `7zip` (даёт `7zz`) | архивы 7z и rar | не распаковываются (при приёмке уходят в карантин) и не показываются; zip и tar читаются и так |
| `dot` (graphviz) | `graphviz` | схемы в сервере документов | схемы отвечают отказом (код 503) с названием программы; служба жива |
| `docker` | `docker.io` | просмотр файлов Office, HTML и метафайлов в контейнере без сети | они не показываются; остальной просмотр работает |
| `systemctl` | `systemd` (обычно уже стоит) | службы и таймер разбора | ставятся вручную, см. «Без служб и без оболочки» |
| `dsh` и node | `nodejs` и `npm` для node; сам `dsh` ставится через `npm`, см. «Оболочка DSH и плагин» | веб-оболочка DSH с разделом Archive | архив работает без неё |
| `tailscale` | в репозиториях дистрибутива его нет: ставится по инструкции проекта Tailscale | шлюз для входа с других машин | архив виден только с машины, где он стоит |

Пакеты ставятся командой `sudo apt install <пакет>`. Чего из этого не хватает на твоей машине, скажет `flyarchive doctor`: он ищет программы по именам
исполняемых файлов из первого столбца (node он не ищет, только `dsh`). Найденный `bwrap` он ещё пробует одним коротким запуском: на обычной Ubuntu 24.04 вне WSL2
песочницу может запрещать настройка системы (непривилегированные пространства имён), и тогда программа есть, а создать песочницу она не может: `doctor` пишет это
отдельной строкой «по желанию» (см. «Разбор частых сбоев»). Версия node: плагин проверен на 22; если в дистрибутиве версия старее, поставь свежую
способом, который описывает проект Node.js.

Шрифт с кириллицей для pdf — не программа, но без него одна возможность не работает: сервер документов собирает pdf (`make_document` с видом pdf) шрифтом, который есть на
машине, потому что стандартные шрифты pdf кириллицы не знают. Он берёт файл `.ttf`, названный настройкой `pdf_font`, а если она пуста — первое из семейств DejaVu Sans,
Liberation Sans, Noto Sans, FreeSans, найденное в каталогах шрифтов системы (`/usr/share/fonts`, `/usr/local/share/fonts`, `~/.local/share/fonts`, `~/.fonts`). Шрифта нет —
pdf с русским текстом не собирается: сервер отвечает отказом (код 503) и называет пакет; текст из одной латиницы собирается и без шрифта. На Debian и Ubuntu шрифт даёт пакет
`fonts-dejavu-core` (`sudo apt install fonts-dejavu-core`); найден ли шрифт, показывает строка про шрифт в `flyarchive doctor`.

Под WSL2 systemd включается строкой `systemd=true` в разделе `[boot]` файла `/etc/wsl.conf` (это настройка WSL, не FlyArchive). Чтобы службы
пользователя поднимались при загрузке без входа в сеанс, включи linger: `loginctl enable-linger <пользователь>`.

### Служба векторов

Обязательная часть: без неё нет ни индексации, ни поиска. Нужна служба с интерфейсом `/api/embed`, как у ollama (проверено с ollama). Адрес — настройка
`embed_url` (по умолчанию `http://127.0.0.1:11434/api/embed`), модель — `embed_model` (по умолчанию `bge-m3`), размерность — `embed_dim` (1024; зашита
в таблицу индекса). Векторы считаются на процессоре (запрос идёт с `num_gpu: 0`); на видеокарту их переводит настройка `embed_gpu`.

**Как поставить и запустить ollama.** Это программа, которая работает службой: отвечает на запросы по HTTP, пока она запущена. Официальная страница загрузки —
[ollama.com/download](https://ollama.com/download) на сайте проекта Ollama. Команду установки возьми оттуда и прочитай её до запуска: здесь она не приводится.
Дальше три шага:

1. Служба должна работать, пока работает архив. Там, где её запускает система, она запущена сама после установки. Там, где не запускает (например, WSL2 без
   systemd), открой соседний терминал, выполни `ollama serve` и не закрывай его.
2. Скачай модель: `ollama pull bge-m3`. Она занимает около гигабайта на диске; скачивание идёт один раз.
3. Проверь: `flyarchive doctor` печатает «служба векторов отвечает: <адрес>, модель bge-m3, размерность 1024». Не отвечает — см. «Разбор частых сбоев»,
   случай «Служба векторов не установлена или не запущена».

### Проверка

```bash
python3 tools/flyarchive doctor              # проверить окружение; ничего не меняет и не создаёт, даже каталог архива
python3 tools/flyarchive doctor --json       # то же для программ
```

Команда проверяет систему, версию Python, библиотеки, программы (найденный `bwrap` ещё и пробует запустить), шрифт с кириллицей для pdf, интерпретатор просмотра,
службу векторов (один запрос: отвечает ли она и та ли размерность),
заведён ли архив, есть ли в нём таблица индекса и задана ли локальная модель. По строке на проверку: `ok`, `НЕТ` (нет обязательного — код возврата 1)
или `по желанию` (нет необязательного: подсказка, что поставить). Той же строкой о недостающем кончаются `flyarchive init` и `flyarchive install`;
служба векторов в них названа словами «служба векторов», а имя настройки адреса (`embed_url`) стоит в подробной строке проверки.
Обязательные библиотеки проверка не только находит, но и загружает: файлы на месте, а загрузка падает — это строка `НЕТ` с первой строкой ошибки; необязательные только
ищутся, потому что загрузка некоторых занимает десятки секунд.

Три строки проверки стоит пояснить. Программа `bwrap` найдена, но песочницу создать не может (так бывает, когда система запрещает непривилегированные пространства имён) —
отдельная строка «по желанию» «программа bwrap найдена, но песочницу создать не может (причина): без неё …» с кодом сообщения `doctor.sandbox_blocked`; в `--json` у неё тот же
`id`, что у найденной программы, `tool.bwrap`. Строка `preview_python` называет интерпретатор, которым просмотр запускает рабочий процесс, и пишет «по желанию», если отдать его
песочнице нельзя безопасно (это отказ `preview.python_outside`, см. «Разбор частых сбоев»). Строка `font` показывает, найден ли шрифт с кириллицей для pdf (см. «Программы»):
шрифт ищется только по именам файлов, ничего не открывается и не создаётся.

Первый запрос к службе векторов может поднимать модель с диска, поэтому ждать ответа можно до минуты. Если за три секунды ответа нет, команда в текстовом
режиме пишет в stderr одну строку, что она не зависла (с `--json` — ничего лишнего). Не ответила за минуту — это отдельное сообщение «повтори проверку»,
а не «служба не отвечает»: так называется отказ в соединении, он приходит сразу. `flyarchive install --dry-run` и `--json`, как и `flyarchive init --json`,
службу векторов не спрашивают.

## Установка

### Одной командой

Запускай установку из того же виртуального окружения, где стоят библиотеки: в файлы служб она записывает интерпретатор, которым её запустили, то есть
интерпретатор окружения (`.venv/bin/python3`), и службы работают с теми же библиотеками. Тот же интерпретатор она записывает в запускалку команды (шаг 5): поставленная команда
тоже идёт с этими библиотеками.

```bash
python3 tools/flyarchive install --dry-run         # что будет записано и запущено; ничего не трогает
python3 tools/flyarchive install                   # архив, службы и таймер, плагин, файл настройки оболочки, команда в пути поиска, запуск
python3 tools/flyarchive install --gateway auto    # то же и шлюз: адрес и имя узла берутся у tailscale
```

Установка идёт по шагам, и каждый печатается:

1. **Архив.** То же, что `flyarchive init`: каталоги `secrets`, `logs`, `index`, `corpus` с правами владельца, служебный токен, пустая база известного,
   пустая таблица индекса с полнотекстовым индексом. Готовое не пересоздаётся и не меняется.
2. **Службы и таймер.** Файлы пишутся из шаблонов `tools/templates` в каталог пользовательских служб systemd. Нет настройки приёмки (`inbox.json`) —
   она заводится с умолчаниями вместе со входящей папкой; готовая не переписывается.
3. **Плагин оболочки.** Исходник `dsh-plugin` кладётся в профиль оболочки DSH.
4. **Файл настройки оболочки** `<каталог архива>/dsh.patch.yml`: подключение сервера MCP архива и плагина. Моделей и их поставщиков в нём нет.
5. **Команда в пути поиска.** Запускалка команды `<каталог архива>/bin/flyarchive` (короткий файл sh, который запускает команду интерпретатором установки) и ссылка `flyarchive`
   на неё в каталоге команд пользователя.
6. **Запуск служб.** `systemctl --user daemon-reload`, затем `enable --now` по порядку зависимостей и таймер разбора.

Ключи:

| Ключ | Что делает |
|---|---|
| `--dry-run` | печатает каждый файл (с содержимым или отпечатком, запускалку команды тоже), ссылку на команду и каждую команду systemctl; ничего не пишет |
| `--no-start` | записывает файлы и не зовёт systemctl; команды, которые надо выполнить самому, печатаются |
| `--no-plugin` | не трогает профиль оболочки |
| `--no-dsh` | не ставит службу оболочки и плагин, даже если `dsh` есть в пути поиска |
| `--gateway auto` | спрашивает у tailscale адрес и имя узла и дописывает в `settings.json` только недостающие ключи, и только адрес из диапазона частной сети (100.64/10) |
| `--gateway off` | шлюз не ставит и частную сеть не спрашивает |
| `--json` | отчёт для программ: путь запускалки команды — в ключе `launcher`, состояние ссылки — в `command` |

Повторный запуск безопасен: файлы переписываются тем же содержимым, чужие службы (не `flyarchive-…`) и соседние каталоги профиля не трогаются, данные
архива не меняются. Нет `systemctl` или каталога профиля оболочки — не сбой: шаг пропускается с пояснением, что повторить. Нет `dsh` в пути поиска —
служба оболочки и плагин не ставятся (иначе служба падала бы с кодом 127 каждые десять секунд), остальное ставится, а установка говорит, что такое
оболочка и как её поставить.

### Что куда пишется

| Что | Куда | Чем задаётся |
|---|---|---|
| данные, журналы, секреты, индекс | каталог архива: `~/flyarchive` или `FLYARCHIVE_HOME` | переменная окружения `FLYARCHIVE_HOME` (в `settings.json` каталога быть не может) |
| службы и таймер | `flyarchive-search.service`, `flyarchive-office.service`, `flyarchive-mcp.service`, `flyarchive-gateway.service`, `flyarchive-dsh.service`, `flyarchive-inbox.service`, `flyarchive-inbox.timer` в каталоге пользовательских служб | настройка `units_dir` (по умолчанию `~/.config/systemd/user`) |
| плагин | `<профиль>/node_modules/flyarchive-dsh-plugin` | настройка `dsh_profile` (по умолчанию `~/.dsh/profiles/web`) |
| запускалка команды | `<каталог архива>/bin/flyarchive` | собирает установка: файл sh с правами 0700 |
| ссылка на команду | `<каталог команд>/flyarchive` (ведёт на запускалку) | настройка `bin_dir` (по умолчанию `~/.local/bin`; пусто — не класть) |
| настройка приёмки | `<каталог архива>/inbox.json` | команда `flyarchive inbox set` и раздел Intake в DSH |
| файл настройки оболочки | `<каталог архива>/dsh.patch.yml` | собирает установка |
| журналы служб | `<каталог архива>/logs/<имя>.log` | шаблоны служб |

Шлюз ставится, только когда заданы `gateway_bind` и `public_url` (или указано `--gateway auto`); иначе установка об этом скажет и поставит остальное.

### Код и данные

Код служб — каталог `tools` репозитория, откуда шла установка. В файл службы пишутся его путь, интерпретатор Python, которым запущена установка, и
каталог архива одной строкой `Environment`: ни адресов, ни имён узла в службах нет, шлюз читает их из настроек. Данные, журналы и секреты лежат только
в каталоге архива; кода там нет, есть лишь запускалка команды `bin/flyarchive`: короткий файл sh, который пишет установка (он называет код и интерпретатор, а кодом не
является). Два практических следствия:

- службы и запускалка команды запускаются тем Python, которым запущена установка: библиотеки из файлов зависимостей должны стоять для него (при виртуальном окружении
  запускай установку из него);
- путь к коду и к архиву не должен содержать пробела и знаков `%`, `"`, `'`, `\`, `$`: systemd разбирает их по-своему, поэтому установка отказывает до
  записи и называет путь.

Рабочую машину ставь из отдельной копии репозитория на выбранной версии, а не из каталога, где идёт разработка: правка в рабочем каталоге меняет то, что
исполняют службы после перезапуска. Версия записана в одном месте, `tools/version.py`: её называют `flyarchive --version`, переходник MCP при знакомстве с клиентом,
описания служб поиска и документов и пакет плагина (`dsh-plugin/package.json`); что изменилось между версиями — в `CHANGELOG.md`.

### Команда в пути поиска

Установка пишет запускалку команды `<каталог архива>/bin/flyarchive` и кладёт ссылку `<bin_dir>/flyarchive` на неё. Запускалка — короткий файл sh с правами 0700: он запускает
файл команды интерпретатором, которым шла установка (`exec '<интерпретатор>' '<код>/flyarchive' "$@"`). Она нужна потому, что у файла команды первая строка
`#!/usr/bin/env python3`, а библиотеки стоят в том Python (чаще всего в окружении), которым ты ставил: ссылка прямо на файл команды в новой оболочке, где окружение не включено,
запускала бы системный Python без библиотек. Через запускалку команду зовут и плагин оболочки (строка `command` файла `dsh.patch.yml`), и `tools/dsh-web-start`, поэтому
поставленной команде окружение включать не нужно. Запускалку установка переписывает при каждом запуске: руками её не правят.

Каталога команд нет — создаёт; ссылка уже ведёт на запускалку — пишет «уже есть»; на месте лежит чужой файл или ссылка на другое — не трогает и называет команду `ln -s`,
которой это делается руками; каталога нет в `PATH` — называет строку для профиля оболочки (`export PATH="<каталог>:$PATH"` в `~/.profile` или `~/.bashrc`). `--dry-run` показывает
запускалку среди файлов и ссылку, которую создал бы или заменил; с `--json` путь запускалки — ключ `launcher`, а в ключе `command` поле `state` называет состояние ссылки: `created`
(создана), `exists` (уже вела на запускалку), `replaced` (ссылка на `tools/flyarchive`, оставшаяся от сборки до версии 0.1, заменена ссылкой на запускалку), `foreign` (чужое имя не тронуто),
`disabled` (настройка `bin_dir` пуста: ссылка не кладётся) или `failed` (ссылку положить не удалось; команду `ln -s` для ручной установки называет ключ `notes`). Пробный прогон ничего не создаёт,
поэтому вместо `created` в нём `free` (имя свободно), а вместо `replaced` — `legacy`. Если службы пока не нужны, `python3 tools/flyarchive install --no-start` запишет файлы и положит ссылку,
но ничего не запустит.

### Обновление

Выбрать новую версию в копии репозитория, включить то же виртуальное окружение, обновить библиотеки, повторить установку и перезапустить службы: установка не
перезапускает то, что уже работает. Окружение нужно включить до установки: службам и запускалке команды записывается тот Python, которым её запустили.

```bash
git pull
. .venv/bin/activate                              # окружение из каталога клона, то же, что при первой установке
python3 -m pip install -r requirements.txt        # новые версии библиотек, если они изменились; возможности по форматам — из requirements-optional.txt
flyarchive install
systemctl --user restart flyarchive-search flyarchive-office flyarchive-mcp flyarchive-gateway
systemctl --user restart flyarchive-dsh    # последним
```

Шлюз перезапускай, только если он установлен. Если плагин или шаблоны служб поменялись, повтор установки обновляет и их.

### Службы

| Служба | Адрес по умолчанию | Что делает |
|---|---|---|
| `flyarchive-search` | `127.0.0.1:8765` (`search_port`) | страница поиска, `/api/search`, `/doc`, `/openapi.json` |
| `flyarchive-office` | `127.0.0.1:8766` (`office_port`) | документы и графика, приём документа, `/openapi.json` |
| `flyarchive-mcp` | `127.0.0.1:8767` (`mcp_port`) | переходник MCP над первыми двумя |
| `flyarchive-gateway` | `<gateway_bind>:8780` (`gateway_port`) | вход с других машин |
| `flyarchive-dsh` | `127.0.0.1:3080` (`dsh_port`) | оболочка DSH с плагином |
| `flyarchive-inbox.timer` | каждые 30 минут | запускает `flyarchive-inbox.service`: разбор входящей папки |

Службы поиска, документов и переходника слушают только петлю (адрес прослушивания не настраивается): наружу смотрит один шлюз.

Одна особенность служб поиска и документов, которой нет в таблице выше:

- **`/openapi.json`.** Службы поиска и документов отдают по этому адресу описание своих инструментов в формате OpenAPI (`http://127.0.0.1:8765/openapi.json` и
  `http://127.0.0.1:8766/openapi.json` при портах по умолчанию). Его читает оболочка, которая берёт инструменты по OpenAPI, а не по MCP. Описание отдаётся
  тому, кто пришёл с токеном (уровня «чтение» и выше), и только на петле: через шлюз этого адреса нет.

```bash
systemctl --user status  flyarchive-search
systemctl --user restart flyarchive-search
systemctl --user list-timers flyarchive-inbox.timer
```

Порядок важен. DSH спрашивает у переходника список инструментов один раз при старте: поднимется раньше — окажется без инструментов и не пожалуется.
Поэтому `tools/dsh-web-start` ждёт порт переходника (до двух минут; порт он проверяет тем же Python, что читает настройки, программа `ss` ему не нужна) и только потом запускает
оболочку, а перезапускать её нужно последней.

Этот совет — тому, кто правит шаблоны служб в `tools/templates` и добавляет в них строки зависимостей: не ставь службам `After=default.target`. Он же их и запускает
(в шаблонах стоит `WantedBy=default.target`), systemd найдёт петлю и молча выбросит из очереди именно DSH. Если шаблоны ты не правишь, этот абзац к тебе не относится.

Служба не читает `.bashrc`. Всё, что нужно процессу, задаётся в юните или в запускающем скрипте: в `PATH` службы оболочки установка кладёт каталог, где
нашёлся `dsh`, `%h/.npm-global/bin` и системные каталоги; ключи читает запускалка (см. «Оболочка DSH и плагин»). Каталог с пробелом в `PATH` службы
не пишется: установка называет его, а служба ищет `dsh` в `~/.npm-global/bin` и системных каталогах. Под WSL запускай установку из оболочки Linux, а не
командой из Windows: иначе в `PATH` окажутся каталоги Windows.

### Что установка не делает

Не ставит библиотеки, ollama и модель векторов, `dsh`, docker, tailscale; не скачивает образ для просмотра Office (это `flyarchive preview setup`); не
задаёт модель. Что осталось сделать самому, печатают `init` и `install` в конце: образ просмотра, локальная модель, входящая папка.

### Как убрать систему

У команды архива нет подкоманды удаления: установка записывает файлы в несколько мест, и убрать их можно руками, по шагам. Все команды ниже выполняешь ты сам;
пути даны по умолчанию, а если ты менял настройки `units_dir`, `bin_dir`, `dsh_profile` или `sandbox_dir` либо каталог архива (`FLYARCHIVE_HOME`), подставь свои. Службы и таймер, которых ты не ставил
(шлюз и оболочку DSH), пропусти: на их имена systemctl ответит, что такого файла нет.

```bash
systemctl --user disable --now flyarchive-inbox.timer        # 1. остановить и выключить таймер разбора и службы
systemctl --user stop flyarchive-inbox.service               #    разбор, если он как раз идёт
systemctl --user disable --now flyarchive-dsh flyarchive-gateway flyarchive-mcp flyarchive-office flyarchive-search
rm -f ~/.config/systemd/user/flyarchive-{search,office,mcp,gateway,dsh,inbox}.service ~/.config/systemd/user/flyarchive-inbox.timer   # 2. убрать файлы служб
systemctl --user daemon-reload                               #    systemd забывает убранное
ls -l ~/.local/bin/flyarchive                                # 3. ссылка команды: должна вести на запускалку в каталоге архива
rm ~/.local/bin/flyarchive                                   #    если ведёт, убрать
rm -r ~/flyarchive/bin                                       #    запускалка команды лежит в каталоге архива: убери её, а данные архива не трогай
rm -r ~/.dsh/profiles/web/node_modules/flyarchive-dsh-plugin # 4. плагин из профиля оболочки DSH
rm -r ~/.local/share/flyarchive-sandbox                      # 5. каталог песочниц оболочек внешних моделей, если ты их запускал
docker image rm gotenberg/gotenberg:8                        # 6. образ просмотра Office; имя записано в preview.json каталога архива
```

Что остаётся и не убирается этими командами:

- **Каталог архива** (`~/flyarchive` или `FLYARCHIVE_HOME`): корпус, индекс, токены, журналы, очередь, карантин, квитанции. Это твои данные: удали его сам, когда
  уверен, что они тебе больше не нужны, и не раньше.
- **Входящая папка и папка возврата.** По умолчанию они лежат в каталоге архива; если ты задавал их `flyarchive inbox set --path`, это отдельные каталоги. Файлы в них
  твои, и они остаются, пока ты их не удалишь.
- **Клон репозитория и окружение `.venv`.** Это обычные каталоги: удали их, когда система не нужна. Оболочка DSH, если ты её ставил, снимается её же средствами
  (`npm uninstall -g @deepseek-ai/dsh`).

## Без служб и без оболочки

Ядро работает командами, без systemd, без DSH, без docker, без tailscale и без локальной модели. Сквозной путь без служб держит тест
`tests/test_clean_install.py`; блок «Первые пять минут» в `README.md` ведёт по нему с примерами из `examples/`.

| Что нужно сделать | Что для этого нужно | Что не нужно |
|---|---|---|
| завести архив, принять документы командой `flyarchive inbox run`, искать командой `flyarchive search` | Linux, Python, обязательные библиотеки, служба векторов | systemd, DSH, docker, tailscale, модель, bwrap |
| разбор по расписанию | `systemctl` и таймер; без systemd — любой планировщик, который зовёт `flyarchive inbox run` | — |
| страница поиска и MCP | запущенные серверы `tools/webui.py`, `tools/office_server.py`, `tools/mcp_server.py` | systemd (можно руками), DSH |
| просмотр pdf, картинок, текста, писем, архивов, календарей | `bwrap` | docker |
| просмотр Office, HTML, метафайлов | `bwrap`, docker и образ (`flyarchive preview setup`) | — |
| проверка документов моделью | локальная модель с интерфейсом OpenAI | без неё `--llm off` |
| описание картинок и сканов | `bwrap` и локальная модель со зрением | облачная модель (картинки в облако не уходят никогда) |
| оболочки внешних моделей в песочнице | `bwrap` | — |
| раздел и вкладка Archive | `dsh`, node, systemd (для службы) или ручной запуск | — |
| вход с других машин | tailscale и шлюз | — |

Ручной запуск служб (каждая — отдельный процесс; каталог архива — `FLYARCHIVE_HOME`, если он не `~/flyarchive`):

```bash
python3 tools/flyarchive init                                  # каталог архива, токен, база известного, таблица индекса
python3 tools/flyarchive inbox set --path ~/flyarchive-inbox --llm off --cloud off --no-timer
python3 tools/flyarchive inbox run --wait                      # разобрать входящую папку сейчас
python3 tools/flyarchive search "запрос"                       # поиск из терминала
python3 tools/webui.py &                                       # страница поиска на search_port
python3 tools/office_server.py &                               # документы и графика на office_port
python3 tools/mcp_server.py &                                  # переходник MCP на mcp_port
```

`--no-timer` у `flyarchive inbox set` только сохраняет настройки: файлы службы и таймера не пишутся и `systemctl` не зовётся; без ключа команда пишет их и включает
таймер (а без systemd сообщает на stderr, что таймер не включён: это не сбой). Разбор без таймера запускается командой `flyarchive inbox run`. Поиск из терминала —
`flyarchive search` (то же, что `python3 tools/search.py`): ключи `-k`, `--source`, `--since`, `--space`, `--today`, `--full`, `--json`. Когда запущен сервер поиска, страница
поиска открывается одноразовой ссылкой: `flyarchive open`.

## Настройки

### Где они лежат и как складываются

Три слоя, сильнее — следующий: **умолчание в коде < файл `settings.json` в каталоге архива < переменная окружения `FLYARCHIVE_<КЛЮЧ ЗАГЛАВНЫМИ>`**.
Каталог архива (`home`) берётся только из переменной `FLYARCHIVE_HOME`, иначе `~/flyarchive`. Файл — объект JSON с ключами из схемы; ключа, которого в
схеме нет, он не принимает (опечатка не проходит молча); он должен принадлежать тебе и не допускать записи группе и остальным, иначе не читается. Значение
настройки в сообщении об ошибке не попадает: там только ключ, источник и что ожидалось. Секретов в настройках нет: ключ локальной модели читается из
переменной `FLYARCHIVE_LLM_KEY` или из файла, путь к которому задаёт `llm_key_file`, а ключ запасной облачной модели — из переменной `FLYARCHIVE_LLM_CLOUD_KEY` или из файла,
путь к которому задаёт `llm_cloud_key_file`.

Пример `settings.json` (каждый ключ необязателен):

```json
{
  "llm_local_url": "http://127.0.0.1:8080",
  "llm_local_model": "имя-твоей-модели",
  "search_port": 8765
}
```

Посмотреть, что действует и откуда взято каждое значение (`default`, `file`, `env`):

```bash
python3 tools/settings.py                    # действующие значения и источник каждого
python3 tools/settings.py --json             # то же для программ
python3 tools/settings.py --get search_port  # одно значение; список — по строке на элемент
```

Справочник всех настроек (ключ, тип, умолчание, границы, описание, переменная окружения) печатает команда:

```bash
python3 tools/settings.py --reference
```

Настройки приёмки (входящая папка, период, проверка моделью, запасная облачная модель, порог, пределы распаковки, описание изображений) в справочник
не входят: они лежат в `inbox.json` каталога архива, их меняют `flyarchive inbox set` и раздел Intake в DSH, а переменные окружения и `settings.json` их
не задают. У каждой настройки одна переменная окружения (`FLYARCHIVE_<КЛЮЧ ЗАГЛАВНЫМИ>`); исключение — ключи моделей: сами они в схеме не лежат, поэтому у них переменные
`FLYARCHIVE_LLM_KEY` и `FLYARCHIVE_LLM_CLOUD_KEY` названы отдельно, а в схеме стоят только пути к файлам ключей. Шрифт для pdf (`pdf_font`) тоже в справочнике: это путь к файлу `.ttf`.

### Справочник настроек

Все настройки схемы, в порядке схемы. Тип и границы значений печатает `python3 tools/settings.py --reference`; у каждой настройки одна переменная окружения.
Списки в переменной пишутся через запятую. Пустое значение у пути, адреса и имени значит «не задано».

| Ключ | Умолчание | Что это |
|---|---|---|
| `home` | `~/flyarchive` | каталог архива; берётся только из переменной `FLYARCHIVE_HOME`, в `settings.json` его быть не может |
| `llm_key_file` | пусто | файл с ключом локальной модели; сам ключ читается только из переменной `FLYARCHIVE_LLM_KEY` |
| `llm_cloud_key_file` | пусто | файл с ключом запасной облачной модели (сам ключ — в переменной `FLYARCHIVE_LLM_CLOUD_KEY`); не задан — серверу уходит заглушка |
| `pdf_font` | пусто | файл шрифта `.ttf` с кириллицей для pdf, которые собирает сервер документов; не задан — шрифт ищется среди обычных системных |
| `env_file` | пусто | необязательный файл с переменными окружения (например, ключ облачной модели) вне репозитория |
| `dsh_profile` | `~/.dsh/profiles/web` | профиль оболочки DSH, в который установка кладёт плагин |
| `units_dir` | `~/.config/systemd/user` | каталог пользовательских служб systemd, куда установка пишет файлы служб |
| `sandbox_dir` | `~/.local/share/flyarchive-sandbox` | каталог песочницы для запуска внешней оболочки |
| `bin_dir` | `~/.local/bin` | каталог команд пользователя: установка кладёт в него ссылку на `flyarchive`; пусто — не класть |
| `search_port` | `8765` | порт службы поиска и страницы поиска |
| `office_port` | `8766` | порт сервера документов |
| `mcp_port` | `8767` | порт переходника MCP |
| `mcp_url` | `http://127.0.0.1:8767/mcp` | адрес переходника MCP, как его видят клиенты |
| `gateway_port` | `8780` | порт шлюза в частную сеть |
| `gateway_bind` | пусто | адрес, на котором слушает шлюз; пусто — шлюз выключен |
| `public_url` | пусто | внешний адрес шлюза для ссылок на документы |
| `public_hosts` | пустой список | имена узла, под которыми шлюз принимает запросы снаружи |
| `hosts` | пустой список | свои имена узла, кроме петли, которые службы принимают в заголовке Host; запрос с чужим именем в нём не обслуживается |
| `dsh_port` | `3080` | порт веб-оболочки DSH |
| `embed_url` | `http://127.0.0.1:11434/api/embed` | адрес службы векторов |
| `llm_local_url` | `http://127.0.0.1:8080` | адрес локальной модели (любого сервера с интерфейсом OpenAI) без `/v1` на конце: `/v1` дописывается само |
| `llm_cloud_url` | пусто | адрес запасной облачной модели без `/v1` на конце; включается отдельно, в настройках приёмки |
| `dsh_patches` | пустой список | дополнительные файлы настройки оболочки DSH с моделями и поставщиками: каждый передаётся оболочке ещё одним `--patch` после основного |
| `env_names` | пустой список | имена переменных, которые запускалка оболочки берёт из файла `env_file`; остальное из файла в окружение не попадает |
| `dsh_llm_key_env` | пусто | имя переменной окружения, под которым оболочка ждёт ключ локальной модели (ключ читается из файла `llm_key_file`); пусто — ключ оболочке не передаётся |
| `embed_model` | `bge-m3` | имя модели векторов; смена требует пересборки индекса |
| `embed_dim` | `1024` | размерность векторов: зашита в таблицу индекса и меняется только вместе с пересборкой индекса |
| `embed_gpu` | `false` | считать векторы на видеокарте (иначе на процессоре) |
| `llm_local_model` | пусто | имя локальной модели для проверки и описания |
| `llm_cloud_model` | пусто | имя запасной облачной модели; включается отдельно, в настройках приёмки |
| `search_half_life_days` | `540` | полураспад веса свежести в поиске, дней: за столько дней вес свежести документа падает вдвое |
| `search_nprobes` | `400` | сколько разделов приближённого индекса просматривает поиск: больше — точнее и медленнее |
| `search_refine` | `30` | во сколько раз больше кандидатов поиск уточняет по исходным векторам |
| `api_snippet_chars` | `420` | сколько знаков текста даётся на одну находку в ответе для модели |
| `api_max_k` | `20` | наибольшее число находок за один вызов поиска |
| `api_budget_chars` | `6000` | общий потолок текста в одном ответе поиска, знаков |
| `mcp_timeout_s` | `300` | сколько секунд переходник MCP ждёт ответа служб |
| `link_ttl_s` | `86400` | срок жизни подписанной ссылки на документ, секунд (сутки) |
| `login_ttl_s` | `300` | срок жизни одноразового кода входа, секунд |
| `session_ttl_s` | `43200` | срок сеанса на странице поиска, секунд |
| `llm_timeout_s` | `180` | сколько секунд ждут ответа модели при проверке |
| `llm_max_chars` | `30000` | сколько знаков документа видит модель при проверке (начало и конец) |
| `llm_max_pages` | `20` | сколько страниц скана проверяется моделью на один документ |
| `submit_max_mb` | `16` | предел размера одного документа, переданного по MCP, МБ; наибольшее значение 17: документ крупнее не пройдёт через тело запроса шлюза |
| `out_keep_hours` | `48` | сколько часов хранятся файлы, созданные сервером документов (графики, схемы, Word, Excel, PowerPoint, PDF) |

### Образцы `settings.example.json` и `sources.example.json`

Оба файла в корне репозитория — **образцы формата, а не готовые настройки**. Все адреса и имена в них выдуманные (`archive.example.com`, `llm.example.com`,
`cloud-model-example`). `settings.example.json` составлен так, чтобы скопированный как есть он не навредил: ключи, которые что-то включают, в нём пусты, как по умолчанию:

- `gateway_bind` и `public_url` пусты: шлюз не ставится, пока ты сам не зададишь оба (как их заполнить — в разделе «Вход с других машин»: адрес этой машины в частной сети
  из диапазона 100.64/10 и внешний адрес вида `http://<имя узла>:8780`, не `https`: шлюз говорит только по HTTP); `flyarchive install --gateway auto` возьмёт недостающее у tailscale;
- `llm_local_model` пуст: локальная модель не задана, и `flyarchive init` и `flyarchive doctor` напоминают её задать. Пока ты не напишешь имя своей модели или не выключишь
  проверку, каждый документ ждёт решения в очереди с причиной «модель не проверила: …» (см. «Локальная модель»);
- `dsh_patches` пуст: свои файлы настройки оболочки с моделями ты называешь сам;
- `llm_key_file`, `llm_cloud_key_file` и `pdf_font` указывают на файлы выдуманного каталога (`~/flyarchive/secrets/llm-key`, `~/flyarchive/secrets/llm-cloud-key`,
  `~/flyarchive/fonts/DejaVuSans.ttf`): пока ты не положишь туда свои, ключ не находится (серверу уходит заглушка), а шрифт для pdf ищется среди обычных.

Остальные ключи в образце — умолчания или выдуманные значения, которые сами ничего не включают (запасная облачная модель включается только отдельно:
`flyarchive inbox set --cloud on`). Бери из образца только те ключи, которые нужны, и подставляй свои значения. Остальное работает и без файла.

`sources.example.json` — образец таблицы источников; зачем она нужна и как ею пользоваться, сказано в следующем разделе. Скопированный как есть образец безвреден: корней
с такими именами в твоём корпусе нет, и обход их пропускает; но ничего и не даёт.

### Таблица источников: свои выгрузки мимо входящей папки

Обычный путь пополнения архива один — входящая папка (см. «Входящая папка и приёмка»): файл, положенный в неё, проходит приёмку и сам попадает в корпус и в индекс, и таблица источников
для этого не нужна. Она нужна только тому, кто кладёт в корпус готовые выгрузки (письма, страницы вики, папки с файлами) сам, в обход входящей папки и приёмки, и хочет, чтобы документы
из них попадали в индекс под понятными базами. Без неё архив работает с одной базой, `входящие`.

Таблица — файл `sources.json` в каталоге архива; формат ключей описан в начале `tools/sources.py`, образец — `sources.example.json`, права как у `settings.json` (файл твой,
запись другим закрыта). Она задаёт три вещи:

- `roots` — какие каталоги `corpus` обходить и как называть базу каждого: вид каталога (`mail` — письма, `pages` — страницы с вложениями, `files` — файлы), база по умолчанию,
  правила «база по части пути» и место при чистке повторов;
- `labels` — подписи баз: они попадают в описание инструмента `search_archive`, которое видит модель;
- `aliases` — под какими прежними именами корни лежали раньше.

Как положить свои файлы и проиндексировать их:

1. Положи выгрузку в каталог корпуса: `<каталог архива>/corpus/<имя корня>/…`.
2. Допиши этот корень в `sources.json`: имя корня — имя каталога из первого шага, `kind` — вид, `source` — имя базы.
3. Выполни `python3 tools/index_more.py` (служба векторов должна работать): он обойдёт корни из таблицы и каталог `входящие`, нарежет текст на фрагменты, посчитает векторы и
   запишет их в таблицу индекса. Он возобновляемый: повторный запуск берёт только то, что ещё не пройдено.
4. Перезапусти службы поиска и MCP: они читают таблицу при запуске, и описание `search_archive` узнает новые базы после перезапуска:
   `systemctl --user restart flyarchive-search flyarchive-mcp`.

Такие файлы приёмка не проверяла: ни правил, ни квитанций, ни сверки с базой известного для них нет, и за их содержимое отвечаешь ты.

## Доступ и токены

Поиск, документы и переходник MCP отвечают только на запрос с токеном. Локальный DSH получает служебный токен сам: запускалка берёт его из
`<каталог архива>/secrets/local.token`.

```bash
flyarchive token add ноутбук                      # только поиск и чтение
flyarchive token add планшет --level full --days 30
flyarchive token list
flyarchive token revoke ноутбук                   # действует со следующего запроса
flyarchive journal -n 30                          # кто и что спрашивал
flyarchive open                                   # одноразовая ссылка на страницу поиска
```

Уровни: `read` — поиск и чтение документов, `full` — ещё создание файлов и передача документов (`submit_document`); служебный `local` — у DSH на машине архива.
Удаление, решения по приёмке и выпуск токенов по MCP не выставлены вовсе.

Токен показывается один раз — при выпуске. В каталоге `secrets` лежат только хеши (`tokens.json`), ключ подписи ссылок (`link.key`) и служебный
токен. Каталог закрыт правами 700, файлы — 600; с более широкими правами службы не стартуют и называют причину в своём логе. Ссылка со страницы поиска
действует столько секунд, сколько задано настройкой `login_ttl_s` (по умолчанию 300, пять минут: этот срок и называет `flyarchive open`), и один раз, сеанс после неё — `session_ttl_s`; подписанная ссылка на документ — `link_ttl_s`
(по умолчанию сутки).

Журнал обращений — `<каталог архива>/logs/access.jsonl`, строка JSON на запрос. Значений токенов в нём нет.

Отказ отозванному или просроченному токену журнал пишет под именем этого токена: в строке его имя, уровень и исход «отказ: токен отозван <время>» или
«отказ: токен просрочен <время>». Клиент получает то же, что и раньше, — 401 и общий текст «токен неверен, отозван или просрочен»: причина ему не
сообщается. Отозван и просрочен одновременно — пишется «отозван». Значение, которого в хранилище нет вовсе, пишется как клиент «-». Имя можно выдать
заново после отзыва: старое значение продолжит получать отказ под тем же именем с пометкой «отозван», новое работает как обычно. Отказ «последний вызов»
токена не обновляет.

```bash
flyarchive journal --client ноутбук -n 50         # отказы отозванному токену видны под его именем
```

В DSH то же самое — Settings → Archive → Access journal с отбором по клиенту.

Удачный список инструментов (`tools/list`) в журнал не пишется намеренно: клиент-ассистент переподключается каждые полчаса, это был бы шум. Что клиент
жив, видно по строкам `mcp:initialize` и по строкам служб, которые выполняют инструменты (поиск, документы): они пишутся под именем клиента.

Инструменты MCP помечены (`annotations` в ответе `tools/list`, по спецификации MCP). Читающие — `search_archive`, `read_document`, `read_document_rich` —
«только чтение» (`readOnlyHint: true`). Создающие — `make_landscape`, `make_diagram`, `make_chart`, `make_document`, `submit_document` — помечены как
меняющие (`readOnlyHint: false`), но не разрушающие (`destructiveHint: false`): они создают файлы и ничего не удаляют и не перезаписывают. У всех
`openWorldHint: false`. Клиент, который спрашивает человека о каждом инструменте без пометок, читающие пропускает сам. Правило держит тест
`tests/test_mcp_annotations.py`.

Проверка руками (службы должны быть запущены):

```bash
curl -s -o /dev/null -w '%{http_code}\n' 'http://127.0.0.1:8765/api/search?q=test'      # 401
curl -s -H "Authorization: Bearer $(cat "${FLYARCHIVE_HOME:-$HOME/flyarchive}/secrets/local.token")" \
  'http://127.0.0.1:8765/api/search?q=test&k=1' | head -c 200                           # находки
```

### Права на файлы

```bash
flyarchive perms check            # каталог архива, его подкаталоги, файлы в secrets и logs
flyarchive perms check --deep     # каждый файл
flyarchive perms fix [--deep]     # 700 на каталогах, 600 на файлах
```

Архив закрыт от других пользователей машины. Всё, что команда и службы создают в каталоге архива, — каталог результатов `out`, журналы, индекс, списки —
создаётся только для владельца при любой маске процесса: команда и службы при запуске ставят маску 077 (службы под systemd получают то же от `UMask=0077`
в файле службы), а каталоги и файлы создаются сразу с правами 700 и 600. Каталоги, которые команда создаёт вне архива (входящая папка, папка возврата, каталог файлов служб), тоже получают права только для владельца. Оболочка в песочнице (`flyarchive run`) получает маску запустившего: её файлы в рабочем каталоге создаются с теми же правами, что и без песочницы. От процессов самого владельца права не защищают — для этого песочница (следующий раздел). Права на код служб
команда не проверяет: код лежит в каталоге репозитория, а не в архиве, и закрыть его от записи другим
пользователям (`chmod go-w`) нужно самому: кто может менять код, получает всё, что могут службы. Об этом команда напоминает второй строкой после
успешной проверки и после исправления, называя каталог, где лежит сама. Отдельного служебного пользователя для служб установка
не заводит: это требует прав администратора.

## Подключение оболочек моделей

```bash
flyarchive connect claude            # Claude Code: фрагмент .mcp.json
flyarchive connect codex             # Codex: фрагмент ~/.codex/config.toml
flyarchive connect opencode          # OpenCode: фрагмент opencode.json
flyarchive connect dsh               # ещё один DSH: накладка на профиль
flyarchive connect generic           # любая другая: адрес, заголовок, проверка через curl
flyarchive connect codex --remote    # оболочка на другой машине частной сети: адрес шлюза
```

Команда печатает три шага: выпуск токена, настройку MCP и запуск. В настройке стоит имя переменной окружения (`FLYARCHIVE_TOKEN`, меняется ключом
`--env`), самого токена там нет. Адрес берётся из настройки `mcp_url` (иначе из `mcp_port`); с `--remote` — из `public_url`, шлюз для этого должен быть
поставлен.

### Оболочка внешней модели в песочнице

Токены закрывают сеть, а не файлы: оболочка, запущенная просто так, читает корпус с диска в обход токенов и журнала. Поэтому оболочки внешних моделей
запускай так (нужен `bwrap`):

```bash
flyarchive token add codex --days 90                 # токен оболочки, показан один раз
export FLYARCHIVE_TOKEN=…                            # положить в окружение, не в файлы
flyarchive run --dir ~/projects/задача --name codex --env FLYARCHIVE_TOKEN --ro ~/.npm-global -- codex
```

| Ключ | Что делает |
|---|---|
| `--dir` | рабочий каталог оболочки, единственное место, куда она пишет |
| `--name` | имя оболочки: у каждой свой домашний каталог, `<sandbox_dir>/<имя>` (по умолчанию `~/.local/share/flyarchive-sandbox/<имя>`) |
| `--env <ИМЯ>` | передать переменную окружения; значение берётся из окружения, в командной строке его нет |
| `--ro <каталог>` | показать каталог только для чтения, например с программой оболочки; его `bin` попадает в `PATH` |

Внутри нет: каталога архива, домашнего каталога владельца (ключи ssh, ключ локальной модели), дисков Windows, сокета docker, шины systemd, `sudo`, чужих
процессов. Сеть общая с машиной: MCP на `http://127.0.0.1:8767/mcp` отвечает по токену.

Отказ до запуска: рабочий каталог в архиве, над архивом или сам домашний; служебный токен `FLYARCHIVE_LOCAL_TOKEN` в `--env`; каталоги из файла
`<каталог архива>/protected-paths` (по пути на строку; сюда вносят, например, копию корпуса на другом диске, которую тоже нельзя отдавать). Запуски
пишутся в журнал: `flyarchive journal` покажет имя оболочки, рабочий каталог и код возврата.

Чего песочница не делает: не ограничивает сеть. Оболочка достаёт до любой службы на петле и до интернета. Архив от неё закрыт токеном, но служба векторов
и сервер модели не принадлежат архиву: его токены их не закрывают.

## Вход с других машин

С другой машины частной сети (tailnet) архив виден через шлюз — единственную службу, которая слушает адрес этой сети. Нужен tailscale на обеих машинах.

Шлюз включают две настройки: `gateway_bind` — адрес этой машины в частной сети (обычно из диапазона 100.64/10; на `0.0.0.0` шлюз не стартует) и
`public_url` — внешний адрес шлюза для ссылок, вида `http://<имя узла>:8780` (шлюз говорит только по HTTP, поэтому не `https`). Имена узла, под которыми
шлюз принимает запросы, кроме взятого из `public_url`, перечисляет `public_hosts`. Проще всего, чтобы установка взяла всё у tailscale:

```bash
flyarchive install --gateway auto       # адрес и имя узла берутся из tailscale ip -4 и tailscale status; дописываются только недостающие ключи
```

Сменились адрес или имя — поправь `settings.json` и перезапусти `flyarchive-gateway`. Адрес частной сети появляется не сразу после загрузки: шлюз
пробует занять его до десяти минут и пишет в журнал, что ждёт.

Что шлюз пропускает снаружи:

```
http://<имя узла>:8780/mcp         инструменты архива, по токену
http://<имя узла>:8780/doc?…       ссылки из ответов: подписаны, без токена, срок link_ttl_s (сутки)
http://<имя узла>:8780/file?…      созданные файлы: то же
```

Остальное снаружи отвечает 404, порты 8765, 8766 и 8767 с других машин недоступны. Токен снаружи действует только в MCP: документ по прямому адресу не открывается
даже токеном, только по подписанной ссылке из ответа. Создание файлов — токеном уровня `full`. Удаление, решения по приёмке и выпуск токенов — только на машине
архива. Размер одного переданного документа ограничен настройкой `submit_max_mb` (по умолчанию 16 МБ).

Подключить клиента:

```bash
flyarchive token add ноутбук --days 90      # на машине архива; токен показан один раз
flyarchive connect codex --remote           # готовая настройка с адресом шлюза
```

На клиенте: адрес `http://<имя узла>:8780/mcp`, заголовок `Authorization: Bearer <токен>`. Проверка с клиента:

```bash
curl -s -o /dev/null -w '%{http_code}' -X POST http://<имя узла>:8780/mcp    # 401
curl -s -X POST -H "Authorization: Bearer $FLYARCHIVE_TOKEN" -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' http://<имя узла>:8780/mcp
```

В журнале такие обращения помечены «через tailnet» и несут адрес узла клиента.

Трафик между узлами частной сети шифрует сам tailscale, поэтому шлюз говорит по HTTP. Не включай `tailscale funnel`: он открыл бы архив интернету. Машина вне
частной сети шлюза не видит; для разовой проверки пробрось порт по ssh и назови в заголовке `Host` имя узла из `public_url`:
`ssh -R 18780:<gateway_bind>:8780 <пользователь>@<машина>` (на той стороне адрес `http://127.0.0.1:18780/mcp`). Для постоянной работы на такую машину ставят tailscale.

## Оболочка DSH и плагин

DSH (DeepSeek Harness) — веб-оболочка для разговора с моделью; в ней появляются раздел и вкладка Archive. Она необязательна: архив работает и без неё
(команда, страница поиска, сторонние оболочки через `flyarchive connect`). Поставить: `npm install -g @deepseek-ai/dsh` (пакет под лицензией MIT, исходники:
`github.com/deepseek-ai/deepseek-harness`), потом повторить `flyarchive install`.

Профиль оболочки (каталог из настройки `dsh_profile`, по умолчанию `~/.dsh/profiles/web`) появляется после первого запуска оболочки: `tools/dsh-web-start`
запускает её с профилем, имя которого — последняя часть пути `dsh_profile` (по умолчанию `web`). Пока каталога профиля нет, установка пропускает плагин и просит повторить после первого запуска. Плагин `flyarchive-dsh-plugin`
(номер версии — в `dsh-plugin/package.json`) написан под DSH на `@deepseek-ai/cordis` `~4.0.4`: если оболочка обновилась и плагин перестал грузиться, архив
остаётся рабочим без него.

Моделей и их поставщиков в установке нет: файл настройки оболочки из репозитория подключает только сервер MCP архива и плагин. Свои файлы настройки
оболочки с моделями перечисляет настройка `dsh_patches`. Ключи в файлы не пишутся: ключ локальной модели запускалка читает из файла `llm_key_file` и
передаёт оболочке под именем из `dsh_llm_key_env`; из файла окружения `env_file` берутся только переменные, названные списком `env_names`. Готовую
переменную окружения файл не перебивает.

Ссылка входа в DSH — со свежим токеном, он меняется при каждом подъёме службы и в закладки не сохраняется:

```bash
tools/dsh-url                                      # напечатать текущую ссылку (читает журнал службы)
systemctl --user restart flyarchive-dsh            # DSH читает плагины при запуске
```

Без systemd оболочку запускают руками: `tools/dsh-web-start` (ссылка появится в консоли). Остановить службу, если она занимает порт:

```bash
systemctl --user stop flyarchive-dsh               # иначе порт dsh_port занят
tools/dsh-web-start
systemctl --user start flyarchive-dsh              # вернуть службу потом
```

Оболочку без `tools/dsh-web-start` не запускай: она поднимется без инструментов архива и без ключей. Их подключает запускалка оболочки: она ждёт переходник MCP, читает служебный токен и ключи (команду архива она зовёт через запускалку команды `bin/flyarchive`, а когда её нет — файлом `tools/flyarchive`), передаёт оболочке файл `dsh.patch.yml` и дополнительные
файлы из `dsh_patches`.

### Вкладка и настройки Archive

Плагин даёт DSH два места для работы с архивом. Экран английский, названия кнопок и разделов ниже даны как на экране; команды в терминале остаются русскими.

- **Вкладка Archive** в правой панели разговора, рядом с Files и Terminal. Здесь повседневная работа: что пришло, что ждёт решения, что было раньше.
  Правая панель есть только в открытом разговоре: в новом разговоре вкладку открывают из путеводителя панели, а на стартовом экране без разговора её
  нет — там пригодится раздел в настройках.
- **Settings → Archive** — то, что меняется редко. Разделы по порядку: Status, Folders, Intake, Tokens, Delete document, Access journal. Очереди и карантина
  в настройках нет: они на вкладке.

Исходник плагина — каталог `dsh-plugin` репозитория, в DSH он лежит в `<профиль>/node_modules/flyarchive-dsh-plugin` и включается строкой в файле настройки
оболочки `<каталог архива>/dsh.patch.yml` (шаблон — `tools/templates/dsh.patch.yml`).

#### Вкладка Archive

- **Строка состояния.** Сколько файлов ждёт во входящей папке («Waiting in the inbox folder»), как часто идёт разбор («Runs every N min» или «No timer: runs
  only on request»), итог последней пачки и число замечаний в ней, число документов, которые ждут описания («Awaiting description»; ноль не показывается).
  Рядом адрес входящей папки и «Copy path».
- **Run now** запускает разбор службой, как `flyarchive inbox kick`. Пока разбор идёт, кнопка неактивна, а под ней виден ход: название этапа, «N of M» (или
  «N done», когда всего ещё не знают), полоса и «Last file». Этапы — в разделе про входящую папку.
- **Needs decision (N)** — очередь и карантин одним списком. В строке: галочка, имя, откуда файл (`review` — очередь, `quarantine` — карантин), баллы, главное
  правило, время. У строки из очереди кнопки Accept и Quarantine, у строки из карантина — Return и Delete. Delete стирает навсегда: он есть только у строки и
  спрашивает подтверждение («Yes, delete forever»).
- **Решения для отмеченных.** «Select all» отмечает все показанные строки. «Accept selected» и «Quarantine selected» действуют на отмеченные строки очереди,
  «Return selected» — на отмеченные строки карантина; кнопка, которой не на что действовать, неактивна. Перед действием вкладка спрашивает подтверждение с
  числом файлов. Решение уходит одним запросом (до 200 путей, больше — несколькими); ответ приходит по каждому пути отдельно: сбой одного показан у его
  строки и остальным не мешает. Любое принятие с вкладки идёт без ожидания индексации: файл сразу в архиве, в индекс его отдаст ближайший разбор.
- **Batches** — история пачек от новой к старой, по 30, «Load more» догружает следующие. В строке пачки: время (по часам браузера), число файлов, итог по
  решениям («accepted», «needs review», «quarantined» и так далее), число замечаний, длительность. Раскрытая пачка показывает замечания прохода и таблицу
  файлов: File, Decision, Owner decision, Location, Score, Main rule. Кнопки над таблицей отбирают файлы по решению. Раскрытый файл — находки, причина, кто
  проверил, дата документа, размер, SHA-256, путь в архиве или куда файл возвращён. У картинки или скана добавляется строка «Described by the model: N pages»
  или «Awaiting description».
- **Просмотр файла.** Раскрытая строка из «Needs decision» и файл в раскрытой пачке показывают содержимое — как это устроено, в разделе «Просмотр файлов».
  Пока файл лежит в очереди, карантине или архиве, он открывается; у возвращённого и стёртого остаются сведения из квитанции.
- **Счётчик и сообщение.** Заголовок вкладки — «Archive (N)», где N — сколько файлов ждёт решения; без ожидающих — «Archive». Когда пачка кончилась и в ней
  есть файлы на решение или замечания, всплывает сообщение «Intake finished: …» с кнопкой «Open» (кнопка только при открытом разговоре). О каждой пачке оно
  показывается один раз и не показывается при загрузке страницы.

Вкладка спрашивает сервер одним общим опросом на все разговоры: раз в 30 секунд, пока страница видна, раз в 2 секунды, пока идёт разбор. Скрытая страница не
опрашивает. Списки очереди и карантина перечитываются, только когда изменились счётчики или номер последней пачки. Нет связи с DSH — вкладка пишет об этом и
продолжает пробовать. Кончился вход — она просит открыть DSH заново по свежей ссылке (`tools/dsh-url`).

#### Settings → Archive

- **Status** — одна строка: сколько ждёт во входящей папке, сколько файлов ждёт решения, сколько документов ждёт описания, итог последней пачки, и подсказка,
  что решения принимаются на вкладке.
- **Folders.** «Inbox folder» — поле и «Change». Перед сменой DSH предупреждает, что архив заберёт всё, что лежит в новой папке. Папка должна уже существовать
  и лежать вне архива, иначе отказ показан у поля. «Returns folder» и «Archive directory» только для чтения, у каждой «Copy path».
- **Intake.** «Run every» (1, 5, 10, 30 или 60 минут), «Score threshold», пределы распаковки («Archive size, GB», «Files», «Compression, to 1», «Nesting
  depth»), «Check with the model», «Cloud fallback model» (с предупреждением, что текст уходит с машины), «Describe images with the local model» и к нему
  «Pages per run» и «Minutes per run». Применяется кнопкой Save. Стёртое число поле оставляет пустым, незаполненное поле названо под полями, и Save ждёт.
- **Tokens.** Список без значений: Name, Level, Issued, Expires, Last used, State (active, revoked, expired). Выпуск — имя, Level (read или full), срок в
  днях; значение показано один раз. Revoke спрашивает «Yes, close access». Служебный токен `dsh-local` отсюда не отзывается.
- **Delete document.** Путь документа, как в выдаче поиска, и подтверждение. Файл не стирается, а переезжает в `<каталог архива>/удалённое/<день>/`.
- **Access journal.** Последние записи с отбором по клиенту; «no token» — запросы без токена. Отказы отозванному токену видны под его именем.

Всё это делается и из терминала: раздел работает через команду `flyarchive`. Выпуск и отзыв токена пишутся в журнал обращений, откуда бы их ни сделали.

```bash
flyarchive token list --json
flyarchive token add ноутбук --level full --days 90 --json
flyarchive token revoke ноутбук --json
flyarchive journal --json -n 100 --client ноутбук
```

Адреса плагина (`/api/flyarchive.*`) закрыты входом DSH: без cookie сеанса — 401, чужой `Origin` или `Host` — 403. Путь к команде плагин берёт из файла
настройки оболочки (строка `command`, её пишет установка, поэтому на установленной системе путь верный), иначе из переменной окружения `FLYARCHIVE_CLI`; если не
задано ни то ни другое, он зовёт команду по имени `flyarchive` из пути поиска команд (без оболочки); не нашлась — отказ с подсказкой, какой настройкой задать путь.

Важно про модели в DSH. DSH ограничивает только запись: читать инструменты модели могут любой файл владельца. Локальная модель никуда данные не отдаёт.
Облачная, выбранная в DSH, через инструменты DSH дотянется до файлов архива в обход MCP и журнала. Если архив содержит то, что нельзя отдавать облаку, не
выбирай облачную модель в оболочке с инструментами DSH, а подключай внешние оболочки через `flyarchive run` (см. «Оболочка внешней модели в песочнице»).

## Входящая папка и приёмка

Положи файл, папку или архив во входящую папку — через период разбора (по умолчанию 30 минут) он в архиве и в поиске. Папка по умолчанию —
`<каталог архива>/входящие`, папка возврата лежит рядом и называется так же с суффиксом `-возврат`: сюда возвращается то, что архив не взял. Любую другую
папку, лежащую вне архива, задаёт `flyarchive inbox set --path`.

```bash
flyarchive inbox status                    # что настроено, что ждёт, чем кончилась последняя пачка
flyarchive inbox run --wait                # разобрать сейчас; --wait ждёт, пока свежий файл отстоится
flyarchive inbox set --period 10           # разбор каждые 1, 5, 10, 30 или 60 минут
flyarchive inbox set --path /srv/inbox     # другая папка; не внутри архива
flyarchive inbox set --path /srv/inbox --must-exist   # то же, но папка уже должна быть: ничего не создаётся
flyarchive inbox set --llm off             # без проверки моделью
flyarchive inbox set --cloud off           # без запасной облачной модели: текст с машины не уходит
flyarchive inbox set --vision on           # описывать картинки и сканы локальной моделью (см. «Описание изображений»)
flyarchive inbox batches                   # история пачек, от новой к старой (ниже)
```

Одна негодная запись разбор не останавливает. Архив, который не распаковался, целиком уходит в карантин. Запись, на которой упала сама приёмка,
возвращается в папку возврата; в квитанции у неё решение `failed` и причина, в выводе команды — строка «замечание». Файл, который не удалось разложить (нет
места, занято имя), остаётся во входящей папке и берётся следующим проходом.

Что происходит с файлом:

| Шаг | Что делается |
|---|---|
| ожидание | файл берётся, когда 30 секунд не менялись его размер и время изменения |
| приёмка | тип по содержимому, распаковка архивов, правила, сверка с архивом, проверка моделью |
| принят | `<каталог архива>/corpus/входящие/<пачка>/…`, индекс, база «входящие» |
| находки | `<каталог архива>/очередь/<пачка>/…` — ждёт твоего решения |
| программа, негодный архив | `<каталог архива>/карантин/<пачка>/…` |
| сверка | sha256 копии равен sha256 исходника — исходник убирается из входящей папки |
| квитанция | `<каталог архива>/квитанции/<пачка>.jsonl`, строка на файл; рядом `<пачка>.meta.json` с длительностью и замечаниями |
| описание | в конце прохода картинка или скан без текста описывается локальной моделью и после этого находится поиском; модель недоступна — долг «ждёт описания» |

Ничего не теряется: из входящей папки убирается только то, чья точная копия сохранена, и то, что не содержимое. Точная копия есть, когда файл принят в корпус, лежит в очереди
или в карантине либо уже был в архиве (точный повтор). Не содержимое — пустые файлы и служебные следы операционных систем: каталог `__MACOSX` и всё в нём, файлы `.DS_Store`,
`Thumbs.db`, `desktop.ini` и файлы `._<имя>`, если они начинаются с подписи формата AppleDouble (так Mac кладёт метаданные рядом с файлом) или лежат в `__MACOSX`. Такой файл получает
решение «пропущен» с причиной в квитанции (например, «пустой файл»), в папку возврата не идёт и не мешает убрать папку или архив, где лежал: zip с Mac, в котором приняты все документы,
убирается целиком. Перечень этих имён один для всех и не настраивается; обычный файл человека с именем на `._` (не начинается с подписи AppleDouble и лежит вне `__MACOSX`) следом
не считается. Всё остальное, что архив не взял, возвращается в папку возврата: не документ (например, картинка gif), письмо, которое уже есть в архиве, но с другими байтами,
файл, пропущенный по шаблону имени (см. «Параметры приёмки»). Архив, в котором осталось такое, возвращается целиком, а следы внутри него остаются как были.
Архивы 7z и rar распаковывает программа `7z`; без неё они не распаковываются и уходят в карантин.

Письма с испорченным текстом (находка `garbled`) задерживаются в очереди до твоего решения.

Без модели проверка не может дать вердикт, и каждый документ получает находку «модель не проверила: …» уровня HIGH: он ждёт решения в очереди при любом
пороге. Пока модели нет, выключи проверку: `flyarchive inbox set --llm off` (см. «Локальная модель»).

Очередь и карантин лежат вне корпуса и в индекс не попадают. Решения по ним — на вкладке Archive в DSH или командой:

```bash
flyarchive queue list                                   # что ждёт решения: файл, баллы, находки
flyarchive queue accept 'очередь/<пачка>/<имя>'         # принять: корпус, индекс, база известного
flyarchive queue quarantine 'очередь/<пачка>/<имя>'     # в карантин
flyarchive quarantine list
flyarchive quarantine return 'карантин/<пачка>/<имя>'   # вернуть в папку возврата; в архив не попадает
flyarchive quarantine delete 'карантин/<пачка>/<имя>'   # стереть, безвозвратно
flyarchive doc delete 'входящие/<пачка>/<имя>' --yes    # убрать документ из поиска и корпуса
```

Принять можно только тот файл, что прошёл проверку: его sha256 сверяется с квитанцией. Убранный документ не стирается: он переезжает в
`<каталог архива>/удалённое/<день>/…`. Вернуть его — положить обратно во входящую папку.

Решения принимаются и пачкой: до 200 путей в одной команде, пути идут после `--`, чтобы имя файла не приняли за ключ. С `--json` ответ всегда
`{"results": [...]}`, по записи на путь в порядке запроса: `ok: true` и прежние поля ответа либо `ok: false` и сообщение об отказе. Негодный путь (нет
файла, файл не из очереди, не сошёлся sha256) остальные не останавливает, код возврата 0. Путей больше 200, список пуст или путь назван дважды — отказ до
первого действия. Без `--json` несколько путей печатаются по строке на путь, сбой уходит строкой в stderr, код возврата 1.

```bash
flyarchive queue accept --json -- 'очередь/<пачка>/<имя 1>' 'очередь/<пачка>/<имя 2>'
flyarchive queue quarantine --json -- 'очередь/<пачка>/<имя 1>' 'очередь/<пачка>/<имя 2>'
flyarchive quarantine return --json -- 'карантин/<пачка>/<имя>'
```

Принятие без ожидания индексации: файл сразу переезжает в корпус и записывается в базу известного, а индексацию команда не ждёт. Она записывает долг
индексации и запускает разбор службой; в ответе `indexed: false`, на экране «В индекс он попадёт следующим разбором». Так принимает вкладка Archive: большой
документ индексируется минуты, а решение не должно висеть. Нет службы таймера или разбор уже идёт — не ошибка: долг записан, его отдаст идущий проход в конце
или следующий.

```bash
flyarchive queue accept --defer-index 'очередь/<пачка>/<имя>'
```

### Параметры приёмки

```bash
flyarchive inbox set --threshold 20        # до скольких баллов документ принимается сам (0–100)
flyarchive inbox set --max-gb 2 --max-files 5000 --max-ratio 100 --depth 3   # пределы на один архив
flyarchive inbox kick                      # запустить разбор службой и не ждать конца
```

Названные значения — умолчания. Программа идёт в карантин, а не проверенное моделью — в очередь при любом пороге.

Служебные файлы. Имён «служебных» файлов по умолчанию нет: `README.md`, журнал `.jsonl` и перечень `.csv` принимаются как обычные документы, и вообще любой текстовый файл с любым
именем — тоже. Если выгрузка кладёт рядом с документами файлы, которые в архиве не нужны (описания, перечни, отчёты о проверке), назови их шаблонами имён (как в fnmatch, без учёта
регистра). Ключ можно повторить; он задаёт список целиком, пустое значение его очищает. Образец записи — шаблоны для файлов-спутников выгрузки, которые в архиве не нужны:

```bash
flyarchive inbox set --service-name '*.tmp' --service-name '*.bak'    # в любой папке
flyarchive inbox set --service-root-name 'index.*'                    # только в корне входящей папки или архива
flyarchive inbox set --service-fate delete                            # что станет с такими файлами: return или delete
```

Эти параметры лежат в `inbox.json` каталога архива: `service_names` — шаблоны для любой папки, `service_root_names` — только для корня входящей папки или архива-файла,
`service_fate` — судьба пропущенного. Файл по шаблону получает решение «пропущен» с причиной в квитанции: «служебный файл выгрузки: перечень, а не документ» (шаблон из `service_names`)
или «служебный файл выгрузки: описание или отчёт о проверке» (из `service_root_names`). Так же пропускается описание письма: файл `.json` рядом с одноимённым письмом `.eml` или
`.msg`; шаблон для него не нужен. Что станет с такими файлами, решает `service_fate`: `return` (по умолчанию) — файл переезжает в папку возврата, а папка или архив, где он лежал,
возвращается по общему правилу; `delete` — файл убирается и возврату папки или архива не мешает. Значение, которого нет среди двух, отклоняется с кодом сообщения
`inbox.bad_service_fate`, прежнее остаётся. Шаблоны и судьба видны в `flyarchive inbox status` и в ответе `flyarchive inbox set`; раздел Intake в DSH их не показывает и при
сохранении оставляет как есть. Пустые файлы и следы систем от `service_fate` не зависят: они убираются всегда.

Смена входящей папки. С ключом `--must-exist` команда ничего не создаёт: папки нет — отказ, настройка и таймер не тронуты; корень и домашний каталог не
принимаются; папка не может лежать внутри архива и не может его содержать. Смена пишется в журнал обращений: служба `cli`, клиент «владелец», старый и новый
адрес. Без ключа команда создаёт недостающую папку. Так меняет папку и «Change» в Settings → Archive → Folders. Папка возврата переезжает вместе с входящей.
Архив заберёт всё, что лежит в новой папке, а то, что осталось в старой, новый разбор не увидит.

Дата документа: свойства файла, затем дата в имени, затем время изменения, затем день приёмки с пометкой. Вложению письма ставится дата письма.

Другая машина или модель с токеном уровня `full` передаёт документ инструментом MCP `submit_document`. Он ложится в эту же папку и проходит ту же приёмку.

Разбор по расписанию — таймер `flyarchive-inbox.timer`, лог — `<каталог архива>/logs/inbox.log`.

```bash
systemctl --user list-timers flyarchive-inbox.timer
tail -20 "${FLYARCHIVE_HOME:-$HOME/flyarchive}/logs/inbox.log"
```

### Пробный разбор пачки: `flyarchive check`

Разбор в папку: архивы распаковываются, каждый файл проходит приёмку и ложится по решению. Источник не изменяется, в архив и индекс ничего не попадает.
Так можно посмотреть, что сказала бы приёмка, не пополняя архив. Шаблоны служебных имён из `inbox.json` действуют и здесь, а пустые файлы и следы систем получают решение «пропущен»,
как при разборе входящих.

```bash
flyarchive check ~/входящие/пачка.zip --into ~/flyarchive/staging/пачка-1
```

Перед разбором нужна база известного — по ней узнаётся то, что уже лежит в архиве. Сборка читает только новое и изменённое, поэтому её можно запускать
перед каждым разбором:

```bash
flyarchive known build
flyarchive known status
```

Письма сверяются по `Message-ID`, остальные файлы — по содержимому. Без базы `flyarchive check` откажет, если не указать `--without-archive`: тогда дубликаты
ищутся только внутри пачки.

В каталоге разбора:

| Что | Зачем |
|---|---|
| `принято/` | прошло приёмку |
| `на-утверждение/` | находок больше порога — решаешь ты |
| `карантин/` | программы, скрипты, архивы с паролем, бомбы |
| `отчёт.md` | сводка: сколько чего, что в карантине и почему |
| `отчёт.jsonl` | строка на каждый файл: решение, баллы, находки, откуда взят |

Пределы на один архив по умолчанию: 2 ГБ распакованного, 5000 файлов, сжатие 100 к 1, вложенность 3. Для большой пачки задаются ключами:

```bash
flyarchive check mailarc.zip --into ~/flyarchive/staging/mailarc --max-gb 80 --max-files 400000 --jobs 16
```

Проверка моделью включается ключом `--llm`. Модель читает только то, что прошло правила и сверку с архивом; находки она может добавить, снять — нет.

```bash
flyarchive check пачка.zip --into ~/flyarchive/staging/пачка --llm               # локальная модель; запасная облачная — если она настроена
flyarchive check пачка.zip --into ~/flyarchive/staging/пачка --llm --no-cloud    # только локальная
flyarchive check пачка.zip --into ~/flyarchive/staging/пачка --llm --llm-jobs 8  # читать по восемь документов разом
```

| Что случилось | Что будет |
|---|---|
| локальная модель ответила | документ проверен, в отчёте её имя |
| локальная молчит `llm_timeout_s` секунд (по умолчанию 180) или сервер сообщает, что загружена другая модель | текст проверяет запасная облачная модель, если она настроена, — текст уходит с машины |
| запасной нет (`--no-cloud`, не заданы `llm_cloud_url` и `llm_cloud_model`) или она тоже молчит | документ на утверждении: «модель не проверила» |
| модель ответила не JSON, и повтор не помог | документ на утверждении, в облако текст не уходит |
| картинка или скан | только локальная модель; без неё скан распознаётся на месте (нужен `docling`), и проверяется текст |

Каталог разбора нельзя класть внутрь корпуса. Каталоги с именем `_карантин` индексатор и база известного не обходят.

История пачек. Источник — квитанции `<каталог архива>/квитанции/<пачка>.jsonl` и рядом `<пачка>.meta.json`: когда шёл проход, сколько секунд и какие были
замечания. У старых пачек этого файла нет: длительность «—», замечаний 0.

```bash
flyarchive inbox batches                                  # 30 последних пачек, от новой к старой
flyarchive inbox batches --limit 100                      # от 1 до 200
flyarchive inbox batches --before <пачка>                 # только старше названной
flyarchive inbox batch <пачка>                            # одна пачка, подробно
```

Номер пачки — `ГГГГММДД-ЧЧММСС`; если две пачки начались в одну секунду, ко второй добавляется `-2`. Список — таблица «Пачка, Время (UTC), Секунд, Файлов,
Замечаний, Итог»; если есть более старые пачки, последняя строка подсказывает команду с `--before`. Одна пачка — по строке на файл: решение приёмки, баллы, где
файл сейчас, решение владельца, если оно было, и у картинок и сканов состояние описания. Где файл сейчас: в архиве, в очереди, в карантине, возвращён в папку
возврата, стёрт, «не хранится» (хранить было нечего: дубликат, пропуск, распакованный архив) и «нет на месте» — по квитанции файл должен лежать в архиве,
очереди или карантине, а его там нет; скорее всего, его убрали руками, и стоит разобраться. Те же данные с `--json`; их показывает блок Batches на вкладке
Archive.

Живой ход разбора. Пока идёт проход, в каталоге архива лежит `inbox-progress.json`: этап, сколько готово из скольких, последний готовый файл, номер пачки,
время начала и последнего обновления. Когда проход кончился, в том числе отказом, файла нет. `flyarchive inbox status --json` отдаёт его в поле `progress`, а
если файла нет, процесса с этим номером нет или запись старше десяти минут — `null`. Вкладка Archive показывает ход под «Run now». Этапы идут в таком порядке:

| Код | Название на экране | Что идёт |
|---|---|---|
| `intake` | Unpacking and rule checks | распаковка архивов, правила, сверка с архивом |
| `model` | Model check | проверка моделью, если она включена |
| `settle` | Filing and de-duplication | раскладка по решениям и сверка копий |
| `index` | Indexing | индексация принятого и долгов индексации |
| `sources` | Cleaning up sources | уборка исходников из входящей папки |
| `vision` | Describing images | описание картинок и сканов, см. «Описание изображений» |

Всего файлов на этапе `intake` может быть неизвестно: архивы раскрываются кругами, число растёт. Пока один документ индексируется или описывается моделью,
запись хода обновляется сама, каждые 20 секунд: живой проход не выглядит брошенным. Проход без новых файлов, но с долгами описания идёт без пачки и начинается
сразу с этапа `vision`.

Если векторы посчитать не удалось (служба векторов не отвечает), документ остаётся в корпусе, а долг — в `<каталог архива>/index/pending.jsonl`. Проход отдаёт
долги в начале и ещё раз в конце: долг, записанный пока он шёл (принятие без ожидания индексации), индексируется этим же проходом. Все правки файла долгов
идут под замком `index/pending.lock`: принятия и проход могут идти одновременно, и ни один долг не теряется и не задваивается. Сколько долгов, показывает
`flyarchive inbox status` («Ждёт индексации»). Второй вид долга — «ждёт описания» у картинок и сканов без текста, см. «Описание изображений».

## Просмотр файлов

Вкладка Archive показывает содержимое файла из очереди, карантина или архива. Файл рисует сервер, а в браузер уходит только картинка и простой текст: сам
файл браузер не получает. Нужен `bwrap`, которым система позволяет создать песочницу (см. «Разбор частых сбоев»).

Рабочий процесс идёт настоящим интерпретатором, которым запущена команда (у виртуального окружения это его базовый интерпретатор). Лежит он в системных каталогах — песочница видит его
сама; лежит вне них (свой Python в домашнем каталоге, pyenv, conda) — каталог его установки привязывается к песочнице только для чтения. Если так отдать его нельзя безопасно, просмотр
отвечает отказом `preview.python_outside`; строка `preview_python` в `flyarchive doctor` называет этот интерпретатор заранее.

| Что за файл | Как показывается | Предел |
|---|---|---|
| PDF, SVG | страницы картинками | 20 страниц, не больше 4 Мп на страницу |
| PNG, JPG, GIF, BMP, TIFF, WEBP | картинка | 2000 точек по длинной стороне |
| текст, код, json, xml, sql, yaml, log, md | простой текст | первые 20 000 знаков |
| письма eml и msg | шапка, текст, список вложений; вложение открывается тем же просмотром, вложение во вложении тоже | текст 20 000 знаков; глубже двух уровней вложения не раскрываются |
| архивы zip, 7z, rar, tar и сжатые | состав: имена и размеры, ничего не распаковывается | 500 строк |
| календарь ics | события: когда, тема, место, число участников | 20 000 знаков |
| Word, Excel, PowerPoint, OpenDocument, RTF, CSV, Visio, EMF, WMF, HTML | через контейнер превращаются в PDF и показываются страницами | файл до 100 МБ, преобразование до 120 секунд |
| программы, неизвестное | только сведения о файле: имя, тип, размер, sha256, пачка, откуда | — |

BPMN, draw.io, видео и звук пока не показываются: для них вкладка пишет «A converter is needed».

Как это защищено, простыми словами. Файл в очереди и карантине не проверен и может быть вредоносным, поэтому команда просмотра сама его не разбирает: она
только считает контрольную сумму потоком. Читает файл рабочий процесс в песочнице без сети: он видит свой входной файл и ничего больше, а память, время и
размер записи ему ограничены ещё до того, как он загрузил библиотеки. Office и HTML открывает контейнер без сети, только для чтения, без прав и с пределами по
памяти, ядрам и времени. Что вернул рабочий процесс или контейнер, проверяется как данные (обычный файл, размер, начало и конец PNG или PDF, описание по
схеме) до записи в кэш. Наружу выходит только PNG и простой текст: разметка и сценарии из файла в ответ не попадают, SVG со сценарием даёт картинку, а
страница вкладки никуда, кроме самого DSH, не обращается.

Из терминала то же самое. Область (`--area`) — `queue`, `quarantine` или `corpus`, путь — как в списках; пути для `corpus` считаются от корня корпуса.
`--member N` открывает вложение письма (до двух ключей).

```bash
flyarchive preview show --area queue -- 'очередь/<пачка>/<имя>'              # что за файл, текст или число страниц
flyarchive preview show --area queue --json -- 'очередь/<пачка>/<имя>'       # то же для программ
flyarchive preview show --area queue --member 0 -- 'очередь/<пачка>/<письмо>.eml'   # вложение письма
flyarchive preview page --area queue -- 'очередь/<пачка>/<имя>' 1 > страница.png   # страница 1 в PNG, в stdout
```

Разовая настройка контейнера. Без неё PDF, картинки, текст, письма, архивы и календарь показываются, а Office, HTML и метафайлы — нет. Нужен docker. Образ с
LibreOffice скачивается один раз отдельной командой; сеть нужна только ей, сам просмотр ничего не скачивает.

```bash
flyarchive preview setup                    # скачать образ gotenberg/gotenberg:8 и записать его дайджест
flyarchive preview setup --image <образ>    # образ уже скачан: записать дайджест без сети
```

Дайджест (`<имя>@sha256:…`) записывается в `<каталог архива>/preview.json`. Контейнер запускается только по записанному дайджесту: тег без дайджеста не
принимается, а если образа с таким дайджестом на машине нет, просмотр отказывает с подсказкой, а не качает его сам. Доступ к docker равен правам
администратора машины: команда запускает один закреплённый образ с фиксированным набором ключей, а имя файла в ключи не попадает.

Пределы. Рабочий процесс: 2 ГБ памяти, 60 секунд процессорного времени, 90 секунд общего срока, не больше двух процессов одновременно (третий ждёт).
Контейнер: 2 ГБ памяти, 2 ядра, 256 процессов, 120 секунд на преобразование — срок стоит внутри контейнера, так что он завершится, даже если команду убили.
Одновременно идёт одно преобразование. Первый показ большого Office-файла долгий, повторный берётся из кэша мгновенно.

Кэш лежит в `<каталог архива>/cache/preview/<sha256>/` и целиком производный: всё в нём пересоздаётся при следующем просмотре. Ключ — sha256 тех байтов, что
рисуются, поэтому у вложения письма свой кэш, а одно и то же вложение из разных писем рисуется один раз. Кэш чистится сам, когда превышен объём, и по команде:

```bash
flyarchive preview clean                  # убрать старше 7 дней и всё сверх 2 ГБ
```

Команда печатает «Убрано: N, освобождено байт: X, в кэше осталось байт: Y». Любая команда `flyarchive preview …` при старте убирает забытые контейнеры
`flyarchive-preview-…` старше пяти минут.

Что видит владелец при отказе. Просмотр не падает: файл показывается сведениями, а под ними причина текстом. На вкладке это «No preview is available for this
file» и пояснение; в терминале то же по-русски. Типичные причины: файл закрыт паролем, это программа или скрипт, изображение больше предела по мегапикселям,
рабочему процессу не хватило памяти или срока, файл больше 100 МБ для контейнера, тип не поддерживается, нет песочницы `bwrap` (или она есть, а создать её система не даёт), контейнер не настроен. Если
файл рисуется другим запросом, вкладка показывает «Rendering…», переспрашивает раз в 2 секунды и сдаётся через три минуты кнопкой «Try again».

## Описание изображений

Картинки и сканы без текстового слоя принимаются в архив, но в индексе текста для них нет, и поиск их не находил. Их описывает локальная модель со зрением:
что это за схема, все надписи дословно, что с чем связано. Описание ложится в индекс фрагментами того же документа, а поиск ведёт на исходный файл. Описание
каждой страницы начинается словами «Описание изображения, сделанное моделью (страница N):», так что оно всегда отличимо от настоящего текста документа.
Запрос к модели и описание — по-русски.

Что описывается: принятые в архив png, jpg, tiff, svg и страницы PDF без текстового слоя. Картинки других форматов (gif, bmp, webp) приёмка не принимает: по содержимому
она узнаёт из изображений только png, jpg и tiff, остальное считает «не документом» и возвращает в папку возврата (а если такая картинка лежит в архиве, возвращается весь архив). Картинка меньше 120 точек по стороне не
описывается. У документа описываются первые 20 страниц. PDF с текстовым слоем в описании не нуждается: его текст идёт в индекс обычным путём.

Что нужно: локальная модель со зрением (принимает картинки в запросе `chat/completions`) и `bwrap`; настройка модели — в разделе «Локальная модель».
Изображения не уходят в облако никогда: запасного облачного пути у этого шага нет, и настройка запасной облачной модели на него не действует. Файл для модели
готовит просмотр, то есть рабочий процесс в песочнице; модели уходит готовая картинка не больше 4 Мп.

Включить и выключить:

```bash
flyarchive inbox set --vision on                        # описывать
flyarchive inbox set --vision off                       # не описывать: картинки принимаются и ждут
flyarchive inbox set --vision-pages 60 --vision-minutes 10   # пределы одного прохода
```

То же — флажок «Describe images with the local model» и поля «Pages per run» и «Minutes per run» в Settings → Archive → Intake. Пока ты не включал и не
выключал описание сам, оно следует за проверкой моделью (`--llm`): проверка включена — включено и описание.

Пределы прохода. За один проход шаг описывает не больше 60 страниц (1–1000) и работает не дольше 10 минут (1–240); остальное остаётся долгом. Запросы идут по
одному, одна страница — один запрос; ответ не длиннее 1 500 токенов, на запрос `llm_timeout_s` секунд (по умолчанию 180). Перед каждым запросом проверяется,
что модель готова: если сервер сообщает перечень загруженных моделей, нужная должна в нём быть, и чужую модель шаг с видеокарты не выгоняет.

Долги «ждёт описания». Картинка или скан принимается как обычно, а за ним записывается долг в `<каталог архива>/index/vision-pending.jsonl`. Долги отдаются
в конце каждого прохода, после квитанций (этап Describing images; проход без новых файлов, но с долгами, тоже его делает), и командой `vision run`. Модель не
отвечает, не загружена, занята другой или описание выключено — не сбой: документ остаётся в архиве, долг ждёт, в замечаниях пачки одна запись с причиной. Сбой
одной страницы остальные не теряет. Страница, которая не далась три прохода, пропускается, и документ закрывается.

```bash
flyarchive vision status                          # включено ли, сколько ждёт описания, сколько описано
flyarchive vision run                             # отдать долги сейчас, в пределах страниц и минут из настройки
flyarchive vision run --limit 20                  # не больше 20 документов за раз
flyarchive vision backfill --limit 200 --dry-run  # старые документы без текста в индексе: показать, что нашлось
flyarchive vision backfill --limit 200            # записать их долгами; описывает их `vision run` или проход
flyarchive vision backfill --limit 200 --source входящие   # только одна база индекса
```

`vision run` настройку «описывать» не спрашивает: команду зовёт владелец. Старые документы архива без текста описываются только по команде и частями:
`vision backfill` без `--limit` отказывает, а сам модель не зовёт, только записывает долги. `--limit` — целое от 1 до 100 000.

Где лежат описания: `<каталог архива>/index/vision/<sha256>.json` (модель, дата, страницы). Файл назван по sha256 документа, поэтому ни имени документа, ни
текста описания в пути нет. Описание хранится отдельно от индекса, чтобы индекс можно было пересобрать без модели: повторная индексация берёт готовые
описания, а описание того же содержимого заново не делается. `flyarchive doc delete` убирает файл описания и долги документа, если то же содержимое не лежит в
архиве под другим путём.

Описание — данные, а не указания. Управляющие знаки из него убраны, длина ограничена, ключ модели затёрт. Если на картинке написано указание для модели, оно
попадает в описание как надпись и ничего не меняет. Описание проходит те же правила, что текст при приёмке: страница с находкой HIGH или CRITICAL в индекс не
идёт, в файле от неё остаются номер страницы и название правила, а в замечаниях пачки запись «описание страницы N не попало в индекс: правила нашли …».

Где видно: `flyarchive inbox status` («Ждёт описания»), `flyarchive inbox batch <пачка>` («описан моделью, страниц: N» или «ждёт описания»), Status и вкладка
Archive («Awaiting description»), блок Batches. Квитанция пачки пишется до описания и после не меняется, поэтому живое состояние берётся из файла описания и
долгов.

## Локальная модель

Локальная модель нужна двум шагам: проверке документов при приёмке и описанию картинок. Моделью служит **любой сервер с интерфейсом OpenAI**
(`<адрес>/v1/chat/completions`), которому ты задал адрес и имя модели; для описания изображений она должна принимать картинки в запросе. Запросы к модели
написаны по-русски, поэтому она должна читать русский.

```json
{
  "llm_local_url": "http://127.0.0.1:8080",
  "llm_local_model": "имя-модели-на-сервере"
}
```

Это содержимое `settings.json`. Адрес `llm_local_url` пишется без `/v1` на конце (оно дописывается само), имя `llm_local_model` — то, под которым модель
называет сервер. Ключ, если сервер его требует, — в переменной окружения `FLYARCHIVE_LLM_KEY` или в файле, путь к которому задаёт `llm_key_file`; в
настройках самого ключа нет.

Что должен уметь сервер и что необязательно:

- Обязательно — ответ на `chat/completions`. Запрос идёт без инструментов, с температурой 0 и дополнительными полями: `response_format` (JSON), `chat_template_kwargs`
  с выключенным размышлением, для облачной точки — `reasoning_effort`. Сервер, который отвечает на них кодом 400, получает тот же запрос ещё раз с одними основными
  полями (модель, сообщения, температура, число токенов); удалось — дальше этой точке в этом процессе шлются только они.
- Необязательно — перечень загруженных моделей `GET <llm_local_url>/running`, который умеют не все серверы. Сервер, ответивший на него кодом 404, 405 или 501, не
  сообщает, что загружено, и модель на нём считается готовой. Если перечень есть, нужная модель должна в нём стоять, а чужая, занявшая видеокарту, дожидается:
  проверка ждёт до `llm_timeout_s` секунд, потом идёт к запасной модели или откладывается; описание изображений чужую модель не выгоняет и откладывается.
  Любой другой сбой запроса перечня — состояние неизвестно, шаг стоит с причиной.

**Что происходит без модели.** Имя не задано (`llm_local_model` пусто) — локальной модели нет, запросов не идёт. Проверка при приёмке тогда не даёт вердикта:
каждый документ получает находку «модель не проверила: …» и ждёт решения в очереди; описание изображений следует за проверкой и копит долги «ждёт описания».
Этого не заметить: `flyarchive init` и `flyarchive doctor` напоминают задать модель. Чтобы работать без неё, выключи проверку и описание:

```bash
flyarchive inbox set --llm off --cloud off
```

Тогда документы, на которых правила ничего не нашли, принимаются сами, а те, где правила набрали баллов выше порога (`--threshold`), ждут решения в очереди.
Проверку моделью можно включить позже, задав `llm_local_model` и выполнив `flyarchive inbox set --llm on`.

**Запасная облачная модель.** Выключена по умолчанию. Чтобы включить, задай `llm_cloud_url` и `llm_cloud_model` и выполни `flyarchive inbox set --cloud on`:
тогда, если локальная модель молчит дольше `llm_timeout_s` секунд, текст документа проверяет облачная — и уходит с машины. Ключ облачной точки задан так же, как у локальной: переменной
`FLYARCHIVE_LLM_CLOUD_KEY` или файлом, путь к которому задаёт `llm_cloud_key_file`; нет ни того, ни другого — точка получает ключ-заглушку `ollama`, как у серверов без ключа. Она получает
и поле `reasoning_effort`, как у ollama-совместимых облачных моделей. Отметка «текст уходил с машины» ставится по точке, которая ответила, а не по имени модели: в отчёте разбора она
стоит, когда документ проверила запасная облачная точка. Картинки и сканы в облако не уходят никогда.

**Пределы проверки.** Модель видит начало и конец документа до `llm_max_chars` знаков (по умолчанию 30 000) и до `llm_max_pages` страниц скана (по умолчанию 20).
Модель только добавляет находки: снять баллы правил она не может и сама в карантин не отправляет. Документ для неё — данные между случайными метками, а не
указания; не JSON после одного повтора — документ на утверждении, и в облако он не уходит.

**Одна видеокарта.** Если локальная модель занимает почти всю видеопамять, модель векторов не должна делить с ней карту: по умолчанию векторы и пересборка индекса
считаются на процессоре (`embed_gpu` выключена). Для плановой работы, пока большая модель выгружена, видеокарту можно включить явно: векторы — настройкой `embed_gpu`
(`FLYARCHIVE_EMBED_GPU=1`), построение индекса — ключом `--gpu` у `flyarchive index optimize`. Описание изображений идёт на самой локальной модели, а не на отдельной, и чужую модель с карты не выгоняет: пока нужная не загружена, документы ждут описания.

## Обслуживание индекса

Индекс — таблица `docs` в LanceDB в каталоге `<каталог архива>/index/lance`; как устроены поиск и таблица, см. `docs/architecture.md`. Свежезаведённая таблица
имеет только полнотекстовый индекс: векторного индекса нет, и поиск по векторам идёт перебором; строки, добавленные после построения индексов, тоже лежат вне них и
ищутся перебором. Пока документов десятки и сотни, это незаметно. Когда их накопятся десятки тысяч, поисковые индексы нужно построить: `flyarchive index optimize`.

```bash
flyarchive index optimize               # построить поисковые индексы (на процессоре); ничего не удаляет
flyarchive index optimize --compact     # то же и уплотнить таблицу: слить фрагменты, убрать старые версии
flyarchive known build                  # база известного: sha256, Message-ID и отпечаток писем; читает только новое
flyarchive known status                 # состояние этой базы
flyarchive index dedupe                 # посчитать повторы писем и файлов почты в индексе (без ключа ничего не меняет)
flyarchive index dedupe --apply         # убрать их
flyarchive index dates                  # посчитать, сколько дат поменяется
flyarchive index dates --apply          # поставить письмам и вложениям настоящие даты (и пересобрать индексы)
python3 tools/index_more.py             # доиндексировать корпус, выложенный в каталог corpus вручную
```

**Поисковые индексы.** `flyarchive index optimize` строит индексы поверх таблицы: полнотекстовый заново (замена атомарна: не вышло — прежний остаётся) и приближённый
векторный IVF-PQ (косинусное расстояние; число разбиений — корень из числа строк в пределах от 64 до 4096). На таблице меньше 20 000 строк векторный индекс не строится:
перебор там быстрее индекса, и команда об этом говорит — это не сбой. Счёт идёт на процессоре; видеокарту включает только ключ `--gpu` (не подошла — счёт идёт на
процессоре, а не отказ). Без `--compact` ничего не удаляется. С `--compact` команда ещё сливает фрагменты таблицы, доводит индексы до всех строк и убирает все версии
таблицы, кроме последней: каждая запись в таблицу создаёт версию, и старые версии занимают место. Уплотнение не делай при идущей записи; при идущем разборе входящих
команда откажет, а таймер разбора на время работы пропустит свой проход. Запускай после большого наполнения и когда поиск по большому индексу замедлился. Нет таблицы —
отказ: сначала `flyarchive init`.

**Чистка повторов.** Одно письмо из нескольких выгрузок ящика должно лежать в индексе один раз. Без ключа `index dedupe` только считает; с ключом `--apply`
удаляет фрагменты лишних копий и сохраняет список убранных путей в `index/dedupe-dropped-<время>.txt`. Файлы корпуса не трогаются. Перед чисткой нужна свежая
база известного (`flyarchive known build`) и копия каталога `index/lance`.

**Настоящие даты.** Без ключа `index dates` считает, сколько дат поменяется. С ключом `--apply` переписывает индекс с настоящими датами (письму — из заголовка,
вложению — дата письма, задачи или страницы), строит векторный и полнотекстовый индексы на процессоре, когда в таблице не меньше 10 000 строк, и меняет каталоги
местами. Если менять нечего, команда пишет «Менять нечего» и ничего не строит. Прежний индекс остаётся в `index/lance.before-dates-<время>`: его можно удалить, когда
поиск устроит.

**Дозаполнение.** `python3 tools/index_more.py` обходит корни корпуса, названные в таблице источников (см. «Таблица источников: свои выгрузки мимо входящей папки»),
и каталог `входящие`, режет текст на фрагменты до 4000 знаков и записывает их с векторами. Он возобновляемый: пройденные файлы пишутся в `index/ingested.txt`. Файл, который не прочитан из-за отсутствия библиотеки формата (docx, xlsx, pptx, msg, pdf),
в этот список не пишется: причина называется один раз на библиотеку (сообщение `lib.missing`), число пропущенных — в итоговой строке, а после установки библиотеки повторный запуск
проиндексирует файл. Каталоги
`_карантин` не обходятся никогда. Для документов, принятых через входящую папку, он не нужен: приёмка индексирует их сама.

Векторы и индекс считаются на процессоре; видеокарту для плановой работы включают явно (см. «Локальная модель»).

## Разбор частых сбоев

**Поиск отвечает 502 или 503 и пишет причину.** 502 — «служба векторов не отвечает»: проверь `embed_url` и что служба запущена (`flyarchive doctor`, строка про службу
векторов). Если в журнале ollama `model "bge-m3" not found`, служба запущена от другого пользователя и смотрит в чужое хранилище моделей: скачай модель туда
(`ollama pull bge-m3` от нужного пользователя) или укажи службе `OLLAMA_MODELS` на нужную папку. 503 — нет библиотеки `lancedb` или таблицы индекса: текст ответа
называет, что поставить или какую команду выполнить (`flyarchive init`).

**Служба векторов не установлена или не запущена.** Поиск отвечает 502, а `flyarchive doctor` в строке `НЕТ` пишет: «служба векторов не отвечает: <адрес> (<причина>). Запусти её и
скачай модель: ollama pull bge-m3; другой адрес — настройка embed_url», а в конце: «Не хватает обязательного: служба векторов». Тот же итог в конце `flyarchive init` и
`flyarchive install`. Что делать по порядку:

1. Проверь, что ollama стоит: `ollama --version`. Команды нет — установи ollama по странице загрузки (см. «Служба векторов»).
2. Запусти службу: под WSL2 без systemd — `ollama serve` в соседнем терминале, не закрывая его; там, где её запускает система, проверь, что системная служба работает.
3. Скачай модель: `ollama pull bge-m3`.
4. Повтори `flyarchive doctor`: должна появиться строка «служба векторов отвечает». Служба слушает другой адрес — задай его в настройке `embed_url`.

Если вместо этого `doctor` пишет «служба векторов не ответила за N с: первый запрос может поднимать модель — повтори проверку», служба есть, но первый запрос ждал загрузки
модели с диска: повтори проверку.

**`flyarchive: command not found` после установки.** Каталог, где лежит ссылка (`bin_dir`, по умолчанию `~/.local/bin`), не в `PATH`. Установка называла строку
для профиля оболочки; пока её нет, зови `python3 tools/flyarchive …`.

**`flyarchive` отвечает «нет библиотеки …».** Команда, которую поставила установка (ссылка `<bin_dir>/flyarchive` на запускалку), идёт интерпретатором установки, и включать окружение ей не
нужно: такой ответ значит, что библиотеки нет в самом этом интерпретаторе. Другой Python запускает команду, когда ты зовёшь `python3 tools/flyarchive …` из каталога клона в
оболочке, где виртуальное окружение не включено. Ответ выглядит так: «нет библиотеки lancedb: без неё нельзя завести таблицу индекса и искать по архиву. Поставить: python3 -m pip install -r requirements.txt».
Включи окружение (`. .venv/bin/activate` из каталога клона) и повтори. Если библиотеки и правда нет, команда из ответа её
поставит. Что именно стоит и чего не хватает, показывает `flyarchive doctor`.

**«FlyArchive работает на Linux; под Windows — в WSL2».** Так отвечает любая подкоманда, кроме справки, если команда запущена не на Linux: например, Python из Windows или на macOS.
Код возврата 2. Открой терминал WSL2 и выполни команду из него; на другой системе архив не запустится.

**Службы не стартуют.** Смотри журнал службы в `<каталог архива>/logs/` и `systemctl --user status flyarchive-<имя>`. Типичное: права на каталог `secrets` или
хранилище токенов шире 700 и 600 (`flyarchive perms check`, `flyarchive perms fix`), настройка с негодным значением (отказ называет ключ и источник, значения в
нём нет), занятый порт.

**Шлюз пишет, что ждёт tailscale.** Адрес `gateway_bind` не появился на машине: проверь `tailscale ip -4`. Шлюз пробует до десяти минут и потом завершается, systemd
перезапускает его. Адрес, которого у машины нет и не будет (например, переписанный из чужой настройки), так и не займётся.

**Все документы уходят в очередь с находкой «модель не проверила: …».** Локальная модель не задана или недоступна (см. «Локальная модель»). Задай `llm_local_model` или
выключи проверку: `flyarchive inbox set --llm off`.

**Архивы 7z и rar уходят в карантин и не показываются.** Нет программы `7z` (её даёт пакет p7zip или 7zip); zip и tar читаются и без неё.

**`no credential for provider route "<имя>"` в DSH.** Оболочка не видит ключ модели: служба не читает `.bashrc`. Задай `llm_key_file` и `dsh_llm_key_env`
(запускалка прочитает файл и передаст ключ под этим именем) и убедись, что файл на месте и твой файл настройки оболочки из `dsh_patches` называет ту же
переменную. Перезапусти `flyarchive-dsh`.

**`EADDRINUSE: address already in use 127.0.0.1:3080`.** DSH уже поднят службой. Останови её или просто открой существующую ссылку (`tools/dsh-url`).

**Модель повторяет один и тот же вызов и не отвечает.** Посмотри журнал обращений: `flyarchive journal -n 30` показывает вызовы, которые дошли до архива. Повторов
в нём нет, а модель зациклилась, — значит, вызов теряется между моделью и архивом, на стороне оболочки. Помогает короткий вызов: для схем бери `make_landscape`, а исходник
для `make_diagram` держи короче трёх тысяч знаков; число вызовов можно ограничить и в системном указании оболочки. Вызовы доходят, но ответ пуст, — следующий случай.

**Пустая выдача при живом индексе.** Сначала проверь, что запрос дошёл до архива: в `flyarchive journal -n 20` должна быть строка поиска под именем клиента. Строки нет — модель
зовёт не `search_archive`, а другой инструмент оболочки: назови `search_archive` прямо в системном указании. Строка есть, а находок нет — ослабь запрос: сними `source`,
`space` и `since`, они сужают поиск; тот же запрос из терминала, `flyarchive search "запрос"`, даёт то же, что видит модель.

**Разбор не находит файлы, которые лежат во входящей папке.** `flyarchive inbox status` называет входящую папку в первой строке: проверь, что это та, куда ты кладёшь файлы.
`flyarchive inbox set --path` без `--must-exist` создаёт недостающую папку, поэтому опечатка или путь Windows вместо пути WSL2 (`/mnt/c/…`) даёт новую пустую папку, а не отказ,
и разбор честно отвечает «Разбирать нечего: …». Исправь путь, лучше с `--must-exist`. Сверяйся с самим архивом: `flyarchive known status` называет число файлов и писем в базе.

**Просмотр отвечает «страница ещё рисуется другим запросом: повтори позже».** На вкладке это «Rendering…», через три минуты «The preview is still not ready» и
кнопка «Try again»; `flyarchive preview show` в этом случае пишет «Файл ещё обрабатывается другим запросом: повтори позже». Преобразование Office идёт по одному
за раз, а рабочих процессов не больше двух; большой xlsx или pptx занимает до 120 секунд. Подожди и нажми «Try again» (в терминале повтори команду): готовое
берётся из кэша. Если ответ не меняется дольше нескольких минут, выполни `flyarchive preview clean`: любая команда `preview` при старте убирает контейнеры
`flyarchive-preview-…` старше пяти минут, а срок внутри самого контейнера — 120 секунд, так что зависший не живёт долго.

**Office, HTML или метафайл не показывается: «образ для просмотра не записан: выполни flyarchive preview setup».** Контейнер не настроен. Те же признаки: «образа <образ> …
нет: выполни flyarchive preview setup», «docker не установлен: Office, HTML и метафайлы без него не показываются», «docker не ответил за N с: проверь, что служба docker работает».
Поставь или запусти docker и выполни `flyarchive preview setup` (или `flyarchive preview setup --image <образ>`, если образ уже скачан). PDF, картинки, текст,
письма и архивы от этого не зависят. BPMN, draw.io, видео и звук покажут «нужен преобразователь: файлы этого типа (…) пока не показываются»: они не сделаны.

**`flyarchive doctor` пишет «программа bwrap найдена, но песочницу создать не может».** Программа стоит, а система не даёт ей создать песочницу, поэтому просмотр, описание изображений
и оболочки внешних моделей не работают (файл без песочницы не разбирается никогда); приёмка, индекс и поиск работают. В скобках причина: код возврата `bwrap` и первая строка его ответа (а если он не запустился или не уложился в срок — вид сбоя или срок). Обычная причина —
запрет непривилегированных пространств имён: на обычной Ubuntu 24.04 вне WSL2 его может ставить система, а в контейнере — сам контейнер. Ищи, как разрешить песочницу для
своей системы, по параметру ядра `kernel.apparmor_restrict_unprivileged_userns` и по профилю AppArmor для `bwrap`; это параметр системы, а не FlyArchive, и менять его решаешь ты.
Проверь результат тем же `flyarchive doctor`.

**Просмотр отвечает «просмотр работает с Python из системных каталогов: … лежит вне них».** Рабочий процесс просмотра идёт интерпретатором, которым запущена команда, и каталог его
установки нужно отдать песочнице; для интерпретатора вне системных каталогов (свой Python, pyenv, conda) это возможно, пока каталог установки безопасен. Отказом `preview.python_outside`
просмотр отвечает, когда интерпретатор лежит не в своём каталоге установки (окружение с копией интерпретатора), каталог установки — первого уровня, домашний каталог владельца или
каталог над ним, либо он совпадает с каталогом архива, лежит в нём или над ним. Тот же отказ называет строка `preview_python` в `flyarchive doctor`. Что делать: поставь библиотеки в окружение,
созданное системным Python (`python3 -m venv`), и повтори установку из него.

**Сервер документов отвечает «нет шрифта с кириллицей для pdf: …».** Это отказ (код 503) на запрос `make_document` с видом pdf и русским текстом: шрифта с кириллицей нет ни в файле из
`pdf_font`, ни среди обычных шрифтов системы, а стандартные шрифты pdf её не знают. Поставь пакет, названный в ответе (на Debian и Ubuntu — `sudo apt install fonts-dejavu-core`), или укажи файл
`.ttf` в `pdf_font`. После пакета повтор сработает сразу; после смены `pdf_font` перезапусти службу документов: `systemctl --user restart flyarchive-office`.

**Документы ждут описания и не описываются.** Число «Awaiting description» в Status и на вкладке не уменьшается, а `flyarchive vision status` показывает «Ждёт
описания: N». Причина названа в замечаниях пачки и у файла в истории пачек: «локальная модель не задана (настройка llm_local_model)», «локальная модель не
загружена: документы ждут описания», «локальная модель не отвечает (…)», «локальная модель не ответила за N с», «видеокарта занята другой моделью (…)» или
«ждёт описания: описание изображений выключено (включить: flyarchive inbox set --vision on)». Это не поломка: файлы уже в архиве, ждёт только их описание, а до
него поиск их не находит: текста для индекса в них нет. Задай и загрузи модель (если сервер загружает её по первому запросу, достаточно один раз спросить на ней
что-нибудь) и выполни `flyarchive vision run`; иначе их отдаст следующий проход. Если на карте чужая модель, подожди: шаг её не выгоняет. Если описание
выключено, включи его: `flyarchive inbox set --vision on`.

**Разбор идёт долго, на вкладке виден этап.** Это не всегда сбой. Смотри этап: `Unpacking and rule checks` на большом архиве — минуты, число файлов растёт, пока
архивы раскрываются; `Model check` — секунды на документ; `Indexing` — минуты на большой документ; `Describing images` — до десяти минут за проход, остальное остаётся
долгом. Проход жив, пока обновляется запись хода: `flyarchive inbox status --json`, поле `progress`, в нём `updated`. Если ход пропал посреди разбора (`progress`
стал `null`, новой пачки нет, файлы лежат во входящей папке), проход, скорее всего, умер: процесса нет или запись старше десяти минут. Следующий проход уберёт
остаток записи и продолжит; можно не ждать таймера: «Run now» или `flyarchive inbox run`. Ответ «Разбор входящих уже идёт — этот запуск пропущен.» — не ошибка:
идёт другой проход, а два разом не нужны.

**Токен отозван, а клиент продолжает стучаться.** В журнале строки под именем клиента с исходом «отказ: токен отозван <время>» (или «токен просрочен <время>»).
Сам клиент видит только 401 и общий текст, причина ему не сообщается, поэтому он не поймёт, что делать. Посмотреть: `flyarchive journal --client <имя> -n 50` или
Settings → Archive → Access journal с отбором по клиенту. Если клиент нужен, выпусти новый токен (после отзыва имя свободно) и обнови его на клиенте; если нет —
убери сервер MCP из его настроек. Строки с клиентом «-» — значение, которого в хранилище нет вообще: опечатка или чужой токен.

## Тесты

Тесты не трогают живой архив, индекс, службы и модель: серверные идут во временных каталогах, на подставной модели и подставной службе векторов; настоящие
видеокарта, ollama и сеть им не нужны. Нужны библиотеки из файлов зависимостей, и тесты идут в том же виртуальном окружении, где они стоят (`. .venv/bin/activate`):

```bash
python3 -m pip install -r requirements.txt -r requirements-optional.txt -r requirements-dev.txt
```

На одних обязательных библиотеках (`requirements.txt` и `requirements-dev.txt`) набор тоже идёт без красного: тест, которому нужна библиотека по формату или
программа, которой нет, пропускается с причиной, называющей её. Чем больше библиотек стоит, тем больше тестов идёт.

**Не меняй файлы репозитория, пока идёт полный прогон.** Один из тестов запускает тесты плагина из каталога репозитория, и правка файлов в этот момент может покрасить
его без вины кода. Если набор покраснел, пока ты что-то правил, повтори прогон.

**1. Python.**

```bash
python3 -m pytest                                  # все тесты; идут около получаса
python3 -m pytest tests/test_inbox.py              # один файл
```

Тестов несколько тысяч, и многие запускают команду архива отдельным процессом, поэтому полный прогон идёт около получаса (на слабой машине дольше). В `pytest.ini` стоит `-q`:
вывод короткий, а итоговая строка (`N passed in …`) остаётся; второй `-q` в командной строке убирает и её, тогда смотри на код возврата и на строки `FAILED`. Тесты плагина (`node --test`) идут внутри этого набора. Тесты, которым
нужны `bwrap`, docker с образом, node, `7z`, graphviz, библиотека по формату, без них пропускаются с названной причиной — пропуск не зелёный, читай итоговые строки
(`-rs`). Тест с настоящей
песочницей пропускается и там, где `bwrap` стоит, а создать песочницу система не даёт (обычная Ubuntu 24.04 вне WSL2, контейнер): причина называет, что именно не работает — нет программы,
она не запускается или пространство имён создать нельзя, и что сказал сам `bwrap`. На Python 3.10 один тест (фрагмент настройки Codex читается через `tomllib`, он в стандартной библиотеке с 3.11) тоже пропускается.

**2. Тесты плагина отдельно** (нужен node 18.15 или новее, в ветке 19 — 19.6 или новее; со старой версией тесты в наборе пропускаются с названной причиной; проверено на 22):

```bash
cd dsh-plugin && node --test test/*.test.mjs
```

**3. Сквозные проверки из интерфейса.** Настоящий DSH с плагином из рабочего каталога и настоящий Chromium: тесты водят браузер по вкладке Archive и по
настройкам и сверяют результат снаружи — запросом по MCP и командой, а не только глазами страницы. Выпуск и отзыв токена (отозванный токен получает 401, обе
попытки видны в журнале под именем клиента), уровни read и full, истёкший срок, значение токена не остаётся ни на странице, ни в хранилищах браузера, смена
папки, периода и проверки моделью, настройка описания изображений, «Run now» и ход разбора, решения по одному и пачкой, просмотр письма с вложениями, удаление
документа.

```bash
bash dsh-plugin/e2e/run.sh                  # весь набор; идёт минуты
bash dsh-plugin/e2e/run.sh -g "токен"       # только тесты, в названии которых есть слово
```

Что нужно на машине (набор ничего не скачивает и не ставит): Linux (подходит WSL), node 20 или новее, Playwright и `@playwright/test`, установленные глобально,
Chromium для Playwright, команда `dsh`, `bwrap`, способный поднять песочницу, python3 с `lancedb`, `pyarrow` и `pymupdf`. Чего-то нет — набор пишет «e2e suite skipped»
с причиной и выходит с кодом 0. Это пропуск, а не пройденная проверка: прочитай вывод. Иначе код возврата — итог тестов.

Набор идёт на одноразовом стенде: свои `HOME`, `DSH_HOME` и каталог архива, подставные `systemctl` и служба векторов, модели нет, порты свободные на петле. Живой
архив, профиль DSH, службы и таймеры он не затрагивает; каждый тест перед первым нажатием сверяет, что адрес и каталог стендовые, и иначе падает, ничего не
нажав. После прогона набор ищет токены клиентов и ссылки входа в своём отчёте и при находке выходит с кодом 1. Переключатели окружения: `BA_E2E_TOOLS` (откуда брать код
серверной части: `worktree` по умолчанию, `head` или каталог), `BA_E2E_PLUGIN`, `BA_E2E_OUT`, `BA_E2E_KEEP=1` (не удалять каталог стенда; нужен только для отладки, в нём
лежат токены стенда — после неё каталог удали).

**4. Документы.** Тест `tests/test_docs_for_reader.py` сверяет `docs/operations.md` и `docs/architecture.md` с кодом: каждый названный путь, команда, ключ, настройка и
служба должны существовать, а следов чужой машины и ссылок на закрытые документы быть не должно.

**5. Ворота публикации.** Для тех, кто выкладывает свой форк. Сторож проверяет каждый отслеживаемый файл перед открытием кода и называет файл и строку: домашние
пути, запретные слова, почтовые адреса не из примеров, адреса сети и имена узлов, похожее на токены и ключи, рабочее имя проекта, отслеживаемые файлы в закрытых
каталогах.

```bash
python3 tests/publication_gate.py --words <файл со списком слов>
python3 tests/publication_gate.py --root <каталог снимка> --words <файл со списком слов>   # чистый снимок, не репозиторий
python3 tests/publication_gate.py --words <файл со списком слов> --json                     # находки и сводка для программ
```

Список запретных слов лежит вне репозитория: в нём как раз те названия организаций, фамилии и имена машин, которым в открытом репозитории быть нельзя, и в
репозитории он сам стал бы утечкой. Путь к нему — ключ `--words` или переменная окружения `FLYARCHIVE_GATE_WORDS`. Содержимое списка не печатается нигде,
печатается только найденное место. Без списка ворота не считаются пройденными: код возврата 2. Коды: 0 — чисто, 1 — есть находки, 2 — ворота не смогли работать (нет
списка, нет git, не открылся каталог). Исключения записываются в `tests/publication_allow.txt` с причиной, разрешённые узлы — в `tests/publication_hosts.txt`.
